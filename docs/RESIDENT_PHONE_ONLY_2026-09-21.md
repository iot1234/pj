# ลูกบ้านเข้าใช้งานด้วยเบอร์ที่ผูกห้องเท่านั้น

## วิธีใช้งาน

เปิด `/resident/login` กรอกเบอร์โทรศัพท์ที่ผู้ดูแลผูกกับผู้พักและห้องที่ยังเข้าอยู่ แล้วกดเข้าสู่ระบบได้ทันที ไม่มีรหัสผ่าน OTP activation code ลิงก์ยืนยัน หรือขั้นตอนยืนยันเครื่อง ไม่ว่าครั้งแรกหรือเปิดจากเครื่องใหม่

หน้าแอดมินยังใช้ username และ password ตามเดิม ไม่มีการเปลี่ยนค่าลับของผู้ดูแล เบอร์ห้องต้องถูกบันทึกโดยผู้ดูแลเท่านั้น ผู้พักไม่สามารถเปลี่ยนเบอร์หรือรหัสห้องจากคำขอเข้าสู่ระบบได้

## การทำงาน

`POST /api/auth/resident/login` รับเฉพาะ `phone` ตรวจชนิดและรูปแบบ แปลงเบอร์ไทย/รูปแบบ +66 แล้วค้นหาผู้พัก active ที่ผูก occupancy active และห้องที่ไม่ถูกลบ ต้องตรงเพียงหนึ่งรายการ ไม่รับ resident_id, room_id หรือ role ที่ผู้ใช้ส่งมาเพื่อเลือกสิทธิ์เอง

ตรวจข้อมูลอีกครั้งภายใต้ transaction และ shared lock ก่อนบันทึก audit และสร้างเซสชัน เซสชันผูก resident, auth_version, เบอร์, occupancy และ room ในแต่ละคำขอ หากเปลี่ยนเบอร์ ย้ายออก หรือยกเลิกบัญชี เซสชันเก่าจะไม่ผ่านการตรวจ เซสชันรหัสผ่าน/activation รุ่นก่อนให้เข้าใหม่ด้วยเบอร์

เก็บสถานะ `auth_method=phone`, `assurance=low`, `phone_verified=false` ทั้งในเซสชันและ audit ไม่อ้างว่าทราบผู้ครอบครองเบอร์ ไม่ใช้ trusted-device token หรือข้อมูลอุปกรณ์เป็นเงื่อนไขให้ลูกบ้านเข้าใช้

หน้าลูกบ้านมีช่องเบอร์เพียงช่องเดียว ล็อกช่องและปุ่มขณะส่ง กัน submit ซ้ำ หากล้มเหลวเก็บเบอร์เดิม แจ้งปัญหา และคืนปุ่มให้แก้ไข/ลองใหม่ ไม่รับคำตอบ API ที่ไม่มี actor ประเภท resident/phone เป็นการเข้าสำเร็จ

เมื่อรับเข้าพักหรือเปลี่ยนเบอร์ หน้าแอดมินแจ้งให้เข้าใช้ด้วยเบอร์ ไม่เปิดหน้าต่างบังคับส่ง activation code และไม่แสดงปุ่มออกคีย์ใหม่ รายการผู้พักแสดงว่าเข้าใช้งานได้โดยไม่ผูกกับ password hash

## ความเสี่ยงที่ผู้ดูแลต้องทราบ

**เบอร์โทรเป็นตัวระบุ ไม่ใช่ข้อมูลลับหรือหลักฐานเจ้าของบัญชี คนที่รู้เบอร์สามารถเข้าแทนและใช้สิทธิ์ของลูกบ้านรายนั้นได้** การจำกัด IP, CSRF, session expiry และการห้ามดูบิลของ resident_id อื่น ไม่สามารถแก้ความเสี่ยงนี้ การยกเลิกเซสชันก็ไม่ป้องกันการเข้าใหม่ด้วยเบอร์ที่ยังใช้งานอยู่ นโยบายนี้ทำตามคำขอให้ใช้เบอร์อย่างเดียว ไม่ใช่การยืนยันตัวตนระดับสูง

ยังเก็บโครงสร้างและข้อมูล activation/password เดิมไว้เพื่อรองรับประวัติและความเข้ากันได้ของโค้ดส่วนอื่น แต่ login ไม่อ่านหรือใช้ค่านั้นแล้ว ไม่มี migration ใหม่และไม่ล้างข้อมูลฐานจริงเพื่อเปลี่ยนนโยบายนี้

## การทดสอบ

PHP unit/contract 125 ผ่าน, JavaScript 147 ผ่าน, MySQL แยก 14 ชุดพร้อม schema audit ผ่าน ชุด phone-only เพิ่ม 17 กลุ่มทดสอบ: ครั้งแรก/+66, ไม่ต้องคุกกี้อุปกรณ์, ข้อมูลคีย์เดิมไม่ถูกใช้, ไม่ให้สิทธิ์แอดมิน, ไม่ให้ดูบิลข้าม resident, ปฏิเสธฟิลด์เลือกสิทธิ์เอง, เบอร์ผิด/ไม่มีห้อง, session ห้องไม่ตรง, เปลี่ยนเบอร์, ปิดบัญชี, session รุ่นเก่า, admin password และ rate limit
