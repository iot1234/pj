# UX/UI เรียบง่ายและป้องกันข้อมูลร่างหาย — 20 กันยายน 2026

## สิ่งที่ใช้งานง่ายขึ้น

ใช้พื้นขาว–เทาและสีน้ำเงินสำหรับปุ่มหลัก ลดเงาและการเคลื่อนไหวของการ์ด/ปุ่ม เมนูแอดมินพื้นขาวและไฮไลต์หน้าปัจจุบัน สีสถานะสำเร็จ รอ และผิดพลาดพร้อมข้อความยังคงอยู่ ไม่ซ่อนคำเตือนเรื่องเงินหรือการลบ

ฟอร์มห้องแสดงข้อมูลหลักก่อน: รหัสห้อง ชั้น ประเภท และค่าเช่า รูปห้อง สิ่งอำนวยความสะดวกและคำอธิบายอยู่ใน “รูปห้องและรายละเอียดเพิ่มเติม” และเริ่มพับไว้เมื่อเปิดฟอร์มใหม่

หน้าเข้าสู่ระบบบนมือถือย่อส่วนแนะนำด้านบนให้เหลือชื่อระบบ เพื่อเข้าถึงช่องกรอกเร็วขึ้นโดยไม่ลบช่องกรอกหรือคำเตือน ขนาดช่องกรอกและปุ่มยังรองรับการแตะ มี focus และโหมดเพิ่มความเปรียบต่าง

## ป้องกันการทำงานผิดพลาด

- ฟอร์มห้องและผู้ดูแลล็อกช่องกรอก/ปุ่มปิดระหว่างส่ง ตรวจสถานะกำลังส่งก่อนอ่านข้อมูล และปฏิเสธ submit ซ้ำแม้มีเหตุการณ์ submit เข้ามาอีก
- บันทึกล้มเหลวคืนปุ่มและเก็บข้อความที่กรอกไว้ บันทึกสำเร็จจึงล้างร่างและปิดหน้าต่าง
- กดปิดหรือ Escape หลังแก้ฟอร์มต้องยืนยันก่อนทิ้งข้อมูล กดยกเลิกการทิ้งจะคงข้อมูลไว้ แก้แล้วเปลี่ยนกลับเป็นค่าเดิมไม่ถามโดยไม่จำเป็น
- การตรวจว่ามีร่างใช้ค่าเริ่มต้นในหน่วยความจำ ไม่บันทึกข้อมูลฟอร์มหรือรหัสผ่านลง DOM attribute, localStorage หรือ sessionStorage
- การป้องกันก่อนออกจากหน้าเดิมยังคงครอบคลุม activation code การตั้งค่าและมิเตอร์ พร้อมเพิ่มฟอร์มห้อง/ผู้ดูแลที่กำลังแก้หรือกำลังบันทึก
- โหลดห้องรับเฉพาะผลจากคำขอล่าสุด ระหว่างโหลดตารางเดิมกดใช้งานไม่ได้ ข้อมูลเก่าถูกล้างเมื่อโหลดล้มเหลว เปลี่ยนตัวกรองไม่ทำให้รายการเก่ากลับมา
- ปุ่มออกบิลไม่พร้อมใช้งานขณะข้อมูลห้องกำลังรีเฟรชหรือโหลดไม่สำเร็จ และ preview เดิมถูกยกเลิกเมื่อเริ่มรีเฟรชห้อง

## ผลตรวจในเครื่อง

PHP unit/contract **110 ผ่าน**; JavaScript interaction และ HTML/source contracts **100 ผ่าน** (เพิ่ม source contracts 6 ข้อ), ไม่มี failed/cancelled/skipped ในชุด JavaScript

Microsoft Edge headless **18 กรณีผ่าน** ใช้ HTML/CSS/JavaScript จริงของโครงการ โดยจำลอง API ทั้งการอ่านและเขียน และบล็อกคำขอออกนอก loopback ไม่มีการสร้างบัญชีหรือแก้ห้องจริง

กรณีเบราว์เซอร์ครอบคลุม: เปิดแอดมินโดยไม่มี JavaScript error; ปิดฟอร์มที่ไม่แก้ไข; ยกเลิกการทิ้งร่าง; แก้แล้วเปลี่ยนกลับ; ปิดระหว่างส่ง; กดบันทึกซ้ำ; บันทึกล้มเหลวแล้วลองใหม่; ฟอร์มผู้ดูแล; โหลดห้องล้มเหลวแล้วเปลี่ยนตัวกรอง; หน้าห้องที่ 1366/768/390/320 พิกเซล; ฟอร์มห้องบนมือถือ; เมนูมือถือ/Escape/คืน focus; หน้าเข้าสู่ระบบทั้งสองบทบาท หน้าห้องว่าง ตั้งค่าและออกบิลที่ความกว้างมือถือ

ตรวจและเปิดดูภาพหน้าจอของหน้าห้อง desktop/mobile หน้าเข้าสู่ระบบ mobile และฟอร์มห้อง mobile แล้ว ภาพและบันทึกทดสอบอยู่ใน `storage/logs/minimal-ui-main-20260920/` ซึ่ง git ignore ไม่รวมใน commit

## ขอบเขต

แก้เฉพาะ stylesheet, template และพฤติกรรมหน้าเว็บ ไม่แก้บริการ PHP ฝั่งธุรกิจ schema ฐานข้อมูล `.env` หรือ APP_KEY ไม่ใช้ credential ของผู้ให้บริการและไม่ส่ง LINE/โอนเงินจริง

ผลเบราว์เซอร์เป็น desktop Edge ที่เปลี่ยน viewport ไม่ใช่การตรวจ Safari/iOS หรืออุปกรณ์มือถือจริง ส่วนการทดสอบ API ใช้ข้อมูลจำลอง จึงไม่ได้ใช้ผลนี้รับรองการชำระเงินหรือ LINE จริง
