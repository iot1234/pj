# ผลตรวจระบบ PHP/MySQL — 15 กันยายน 2026

ผลที่มีหลักฐานในรอบนี้แสดงว่าเส้นทางหลักตั้งแต่จองห้อง รับเข้าพัก จดมิเตอร์ ออกบิล จนถึงย้ายออกทำงานได้บนฐานทดสอบแยก และพบจุดที่ต้องปรับเพื่อป้องกันการสูญเสียข้อมูลที่กรอกและการเข้าใจผิดเรื่องการชำระเงิน ยังไม่สามารถรับรองว่าทุกฟีเจอร์ถูกต้อง 100% หรือพร้อมใช้งาน production เพราะการเชื่อมต่อผู้ให้บริการและสภาพแวดล้อมจริงบางส่วนยังไม่ได้ทดสอบ

ผลทดสอบหลังแก้ไขครอบคลุม regression ของการโหลดมิเตอร์และตัวตรวจ runtime/schema แล้ว คำเตือนที่เหลือเป็น integrations ที่จงใจไม่ได้ตั้งค่าบนฐานทดสอบ จึงยังไม่ใช่การรับรองบริการภายนอกหรือเครื่อง production

## ขอบเขตและวิธีตรวจ

- ตรวจ `php-mysql` ตาม FR-01–FR-16 ใน [FEATURE_MATRIX.md](FEATURE_MATRIX.md) และขอบเขตเดิมใน [QA_REPORT.md](QA_REPORT.md) ไม่ได้นำผลตรวจเก่ามานับเป็นผลทดสอบใหม่
- อ่าน route, service, validation, authorization และกฎฐานข้อมูล พร้อมรัน PHP tests, MySQL lifecycle, HTTP และ browser บนข้อมูลทดสอบ
- ใช้ PHP 8.5.8 และ Oracle MySQL 8.4.10 ในสภาพแวดล้อม local ที่แยกฐานและ storage จากระบบเดิม บัญชี runtime ทดสอบมีเฉพาะ `SELECT`, `INSERT`, `UPDATE`
- `newap` เป็นระบบอ้างอิง ไม่ได้แก้หรือรับรองการทำงานของเวอร์ชันนั้น หากระบบที่ใช้งานจริงเป็น `newap` หรือ `ap` ต้องตรวจแยกอีกครั้ง
- ตรวจความใช้ง่ายในเชิงเทคนิค เช่น การนำทาง การแสดงสถานะ การยืนยันก่อนทิ้งข้อมูล การคืนปุ่มเมื่อผิดพลาด และการแสดงผลบนมือถือ ไม่ได้ทำ user research หรือทดสอบกับกลุ่มผู้ใช้จริง

## ความครอบคลุม FR-01–FR-16

คำว่า “ตรวจแล้ว” ในตารางหมายถึงตรวจตามกรณีและระดับที่ระบุ ไม่ได้หมายถึงผ่านทุกค่าป้อนเข้า ทุก browser หรือทุกสถานการณ์ concurrent ที่เป็นไปได้

| FR | ฟีเจอร์ | หลักฐานและผลรอบนี้ |
|---|---|---|
| FR-01 | ดูห้องว่าง ประเภท ราคา รูป และสิ่งอำนวยความสะดวก | HTTP คืนห้องว่างและตัดห้องที่จองออก; browser แสดงห้อง ค้นหา และคืนตัวกรองได้; อ่าน allowlist ของรูปและการซ่อนห้องที่ลบแล้ว |
| FR-02 | จองห้องด้วยชื่อและเบอร์ | HTTP จองสำเร็จ คำขอเดิมคืนรายการเดิม และคำขอที่สองจองห้องซ้ำไม่ได้; ตรวจโค้ด normalized phone, quota, hold expiry และ unique guards |
| FR-03 | ผู้พักเข้าสู่ระบบ | HTTP activation ตั้ง password และปฏิเสธสิทธิ์ Admin; browser login ด้วย password ได้; unit/lifecycle ตรวจอายุ session, การใช้ activation และการเพิกถอนสิทธิ์ |
| FR-04 | ดูบิลและสถานะของตน | HTTP/browser เห็นบิลของผู้พักทดสอบ และ HTTP ปฏิเสธ ID บิลที่ไม่มีอยู่กับ administrative evidence; query จำกัด resident จาก session; lifecycle ตรวจสถานะหลังจำลอง verified payment การยิง ID ที่ไม่มีอยู่ไม่ใช่หลักฐานว่าทดสอบข้ามบิลผู้พักจริงสองรายแล้ว |
| FR-05 | ดูและแก้ข้อมูลส่วนตัว รวมผูก LINE | HTTP แก้ชื่อ/email ได้และปฏิเสธการแก้เบอร์ผ่าน Resident API; lifecycle ตรวจ LINE binding, stale session, code revocation และการผูกชนกันแบบ local; การส่งรหัสผ่าน OA จริงยังไม่ทดสอบ |
| FR-06 | จัดการบัญชีผู้ดูแล | HTTP เพิ่ม/แก้/ปิดบัญชี Admin และยืนยันว่าการปิดเพิกถอน session เดิม; แยก session Owner/Admin ปฏิเสธ Admin ธรรมดาจาก endpoint เฉพาะ Owner และปิดบัญชี Owner ของตนไม่ได้; ตรวจ unit/source ของ last-owner guard |
| FR-07 | เพิ่ม แก้ และลบห้อง | HTTP เพิ่ม/แก้/ลบห้องว่างได้ ห้องที่ลบไม่ปรากฏใน public; ปฏิเสธเลขห้องซ้ำ/ข้อมูลผิดและห้ามลบห้องที่มีผู้พัก; ตรวจ soft delete และ room validation |
| FR-08 | สถานะว่าง จองแล้ว และมีผู้พัก | HTTP ตรวจ available → reserved → occupied; lifecycle ตรวจคืนเป็น available หลัง move-out; สถานะคำนวณจาก booking/occupancy ไม่รับสถานะที่ผู้ใช้กรอกเอง |
| FR-09 | ยืนยัน ยกเลิก และรับเข้าพักจากการจอง | HTTP ยืนยันและรับเข้าได้พร้อม opening meters; ยกเลิก pending แล้วห้องคืนเป็นว่างและ replay เก่าถูกปฏิเสธ; lifecycle ตรวจ replay คำขอรับเข้าเดิมและ rollback เมื่อมิเตอร์ทับเดือน |
| FR-10 | ผู้พักปัจจุบันและวงจรการย้ายออก | Browser เปิดหน้าผู้พัก; HTTP ปฏิเสธ move-out เมื่อค้างชำระ; lifecycle ย้ายออกได้หลัง paid แล้วล้าง credential/เพิกถอน session; ตรวจโค้ดเงื่อนไขบิลครบเดือนและประวัติที่เกิดภายหลัง |
| FR-11 | จดมิเตอร์รายเดือน | HTTP บันทึกได้ ปฏิเสธเลขย้อนกลับและการแก้หลังออกบิล; lifecycle ปฏิเสธ chain ที่ไม่ตรง; browser และ regression tests ยืนยันการเก็บ draft เมื่อยกเลิกนำทาง และล็อกตารางระหว่างโหลดช้า |
| FR-12 | ค่าก่อนหน้าและหน่วยใช้อัตโนมัติ | Lifecycle ตรวจ opening baseline และ occupancy ที่ผูกกับมิเตอร์; HTTP คำนวณน้ำ/ไฟในบิลได้ตรง; ผู้ใช้กำหนด previous/units เองไม่ได้ตาม allowlist |
| FR-13 | Preview และออกบิลหลายห้อง | HTTP เปลี่ยนมิเตอร์แล้ว token เก่าใช้ไม่ได้ ยอดตรงและไม่ออกซ้ำ; lifecycle ตรวจ current-period confirmation และกฎฐานข้อมูลที่ไม่ให้สร้าง paid bill โดยไม่มีหลักฐาน |
| FR-14 | ส่งบิล LINE รายห้อง/ทั้งเดือน | Lifecycle เข้าคิวผู้รับที่มี proof และหยุด reminder เมื่อมี pending payment; worker/contract tests ผ่าน; ยังไม่ทดสอบ push, reply, quota หรือ provider acknowledgment จริง |
| FR-15 | QR PromptPay ตามยอดบิล | Unit ตรวจ payload/CRC และ readiness guard; HTTP ปฏิเสธ QR เมื่อการตั้งค่ายังไม่พร้อม และ browser แสดงคำแนะนำพร้อมซ่อนช่องทางชำระ; ยังไม่โอนเงินจริงจาก QR |
| FR-16 | อัปโหลดและตรวจสลิป | Unit/source ตรวจไฟล์ private, MIME/ขนาด, idempotency, lease และกฎผลตรวจ; HTTP ยืนยัน fail-closed เมื่อ provider ไม่พร้อม; lifecycle จำลอง verified result ที่ฐานข้อมูล ไม่ใช่ upload/ตรวจสลิปจริงกับ SlipOK/EasySlip |

## จุดที่พบและการแก้ไข

1. **คลิกเมนูจดมิเตอร์ซ้ำทำให้ค่าที่ยังไม่บันทึกหาย** — เดิมมีคำถามยืนยันเฉพาะเมื่อเปลี่ยนไปหน้าอื่น แต่คลิกเมนูเดิมเรียกโหลดข้อมูลใหม่ได้ แก้ให้ถามก่อนทิ้งข้อมูลทั้งสองกรณี; browser ยืนยันว่ากดยกเลิกแล้วค่าเดิมอยู่ และยืนยันแล้วโหลดค่าใหม่
2. **ปิดฟอร์มขณะรับเข้า/เพิ่ม/แก้ผู้พักอาจทำให้ผลตอบกลับกระทบฟอร์มรอบถัดไป** — ล็อกการปิดระหว่างบันทึก และจับชื่อ/ห้องสำหรับส่งมอบ activation code ก่อนรอคำตอบ เมื่อสำเร็จหรือผิดพลาดคืน controls ตามสถานะจริง
3. **การโหลดรายการหลังบันทึกรอบเก่าอาจปลดล็อกงานบันทึกรอบใหม่** — พบจาก deferred-response test และแก้ cleanup ให้ทำครั้งเดียวต่อคำขอ ก่อนปิดฟอร์มและก่อนรอโหลดรายการซ้ำ ชุดทดสอบตรวจทั้ง success, error และเปิดฟอร์มรอบใหม่ระหว่างโหลด
4. **ข้อความปิดสลิปค้างอาจทำให้เข้าใจว่าต้องโอนหรือส่งไฟล์เดิมใหม่** — เปลี่ยนปุ่มเป็น “ปิดรายการถาวร” และอธิบายว่าตรวจซ้ำรายการนี้ไม่ได้ ส่งไฟล์เดิมได้ผลเดิม หากโอนเงินจริงแล้วต้องติดต่อผู้ดูแลตรวจยอดก่อนโอนซ้ำ ไม่มีการเปลี่ยนกฎ immutable payment หรือการป้องกันใช้สลิปซ้ำ
5. **เริ่มโหลดมิเตอร์แล้วตารางเดิมยังแก้ได้ก่อนผลตอบกลับมาทับ** — แก้ให้ตารางรับ input/บันทึกไม่ได้ระหว่างโหลด คืนสถานะล็อกเดิมเมื่อโหลดผิดพลาด และให้เฉพาะคำขอล่าสุดคืน controls; เปลี่ยนเดือนแล้วไม่แสดงแถวเดือนเก่าใต้ตัวเลือกเดือนใหม่ ชุด regression ตรวจ 8 กรณีส่วนนี้และ browser จำลองการโหลดช้ายืนยันผ่านแล้ว

ไฟล์ที่เกี่ยวข้องคือ `public/assets/js/app.js`, `templates/admin/console.php`, ชุดทดสอบ interaction ใน `tests/*.test.js` และ `.github/workflows/ci.yml` ซึ่งเพิ่มการตรวจ JavaScript ใน CI

## การป้องกันความผิดพลาดที่ตรวจพบในระบบ

- คำขอเปลี่ยนข้อมูลต้องผ่านสิทธิ์และ CSRF; Resident จำกัดการเข้าถึงบิล/โปรไฟล์ของตน และ Owner ควบคุมบัญชีผู้ดูแลกับ integrations
- ขั้นตอนจอง รับเข้า มิเตอร์ บิล และการชำระใช้ transaction, row locks และกฎ unique/foreign key/CHECK/trigger เพื่อกันข้อมูลค้างครึ่งขั้นตอนหรือการสร้างซ้ำ
- ยอดเงินคำนวณบน server ด้วยเลขที่รักษาทศนิยมสองตำแหน่ง เก็บ snapshot บิล และผูก preview token กับข้อมูลที่ใช้คำนวณ
- มิเตอร์ปฏิเสธเลขย้อนกลับ ประวัติที่ไม่ตรง และการแก้หลังออกบิล; ย้ายออกไม่ได้เมื่อยังมีบิลค้างหรือขาดบิลตามช่วงเข้าพัก
- ผู้ให้บริการที่ยังไม่พร้อมหรือผลไม่ชัดเจนไม่ทำให้บิลเป็น paid; การทดสอบผล verified ใน lifecycle เป็นข้อมูลจำลองที่ยังต้องผ่านกฎความสัมพันธ์ของฐานข้อมูล

การมี controls เหล่านี้และผลผ่านในชุดทดสอบไม่ใช่หลักฐานว่าป้องกันความผิดพลาดได้ทุกชนิด โดยเฉพาะข้อมูลธุรกิจที่ผู้ใช้กรอกถูกชนิดแต่ไม่ตรงความจริง

## ข้อจำกัดที่ผู้ใช้งานต้องเข้าใจ

- **เปลี่ยนผู้พักในห้องเดิมภายในเดือนเดียวกันยังทำไม่ได้** ตามนโยบายมิเตอร์/occupancy รายเดือนใน `BookingService` แม้ย้ายออกแล้วห้องแสดงว่าง วันที่รับผู้พักใหม่ต้องไม่ทับเดือนของผู้พักเดิม ควรแสดงวันที่รับเข้าได้ใน UI หากจะพัฒนาความสะดวกส่วนนี้ต่อ
- **Provider duplicate ที่ไม่ยืนยันผลเดิมอาจค้าง pending** เช่นผู้ให้บริการตรวจสำเร็จแต่ระบบไม่ได้บันทึกผล ต้องให้เจ้าของตรวจสอบยอดและกระทบยอดกับผู้ให้บริการก่อนตัดสินใจต่อ การปิดรายการไม่ทำให้บิล paid และไม่ควรถูกตีความว่าต้องโอนใหม่ ไม่มีทางลัดอนุมัติ paid โดยไม่มีหลักฐาน
- กฎการจ่ายบางส่วน คืนเงิน เปลี่ยนบิลที่สรุปแล้ว หรือแบ่งค่าเช่าระหว่างผู้พักในเดือนเดียวกันไม่อยู่ใน FR-01–FR-16 จึงไม่ได้เพิ่มเองในงานตรวจครั้งนี้

## สิ่งที่ยังไม่ได้ยืนยันในรอบนี้

- LINE OA/Developers จริง: webhook signature/reply/push ผ่านบริการภายนอก, การเพิ่มเพื่อน ผูก/ยกเลิกบัญชี, quota และ retry acknowledgment
- SlipOK/EasySlip ด้วยสลิปจริง: ยอด/ผู้รับถูกและผิด, สลิปซ้ำ, timeout, 429, provider duplicate และการกู้รายการที่ไม่ทราบผล
- HTTPS/TLS, HSTS, reverse proxy, trusted proxies, firewall และค่าของเครื่อง production
- Build/run Docker production image และการทำงานร่วมกันของ worker/cron หลาย process บนเครื่อง deploy รอบนี้ การมี CI configuration ไม่เท่ากับมีผล CI run ผ่านแล้ว
- การกู้ backup ที่ทดสอบ restore ฐานข้อมูล ไฟล์สลิป private และ key ที่สอดคล้องกันจริง
- Load/performance, การใช้งานยาวต่อเนื่อง, browser/อุปกรณ์ทุกแบบ และการทดสอบกับผู้ใช้จริง
