# QR พร้อมเพย์ยอดไม่ซ้ำ และส่งสลิปทาง LINE เมื่อเว็บไม่พร้อม

## วิธีใช้งานลูกบ้าน

เปิดบิลแล้วกด **แสดง QR พร้อมเพย์** ระบบจองยอดบิลเดิมบวกสตางค์ 0.01–0.99 บาท เช่น บิล 100.00 บาทอาจได้ยอดโอน 100.25 บาท อีกบิลที่เท่ากันจะได้ยอดอื่นในช่วงที่ยังไม่ถูกจอง เมื่อเปิดบิลหรือรีเฟรชอีกครั้งยังได้ยอดเดิม ไม่สุ่มใหม่ในเบราว์เซอร์

แสดงยอดบิล ส่วนต่างสตางค์ และยอดที่ต้องโอนแยกชัดเจน ห้ามปัดเศษหรือแทนเลขหลังจุดทศนิยมของยอดเดิม กรณีบิล 100.75 บาทจะเป็น 100.75 บวกส่วนต่าง ไม่ใช่เปลี่ยนให้เป็น 100.xx โดยตัดสตางค์เดิมทิ้ง

สร้าง QR ได้แม้ยังไม่ได้เลือกผู้ตรวจสลิป/คีย์ไม่ครบ/ตรวจสลิปไม่พร้อม แต่ยังต้องมีบัญชี PromptPay ที่ตั้งค่าไว้และโครงสร้างจองยอดที่ถูกต้อง บิลที่ชำระแล้วหรือมีสลิปรอตรวจอยู่ไม่ชวนให้โอนซ้ำ

เมื่อเว็บแนบสลิปไม่ได้ ให้กด **เปิด LINE พร้อมเลขบิล** ในหน้าบิล กดส่งข้อความ แล้วแนบรูปสลิปเดิมในแชตนั้นให้ผู้ดูแลตรวจยอดเงินจริง ปุ่มไม่ส่งข้อความหรือรูปให้เอง และไม่เปิดแอปธนาคารเพื่อโอนใหม่

บอทตอบคำแนะนำเมื่อรับข้อความแจ้งชำระหรือเหตุการณ์รูปจากแชตส่วนตัวที่ผ่านการตรวจลายเซ็น **ยังไม่ดาวน์โหลดรูปจาก LINE มาเก็บในเว็บ และไม่ยืนยันเงินอัตโนมัติจากรูป** ผู้ดูแลต้องดูแชตของ LINE OA และตรวจรายการเงินเข้า หากยังไม่ตั้ง Basic ID ระบบแจ้งให้ติดต่อสำนักงาน ไม่ส่งไป URL ที่เดาหรือบริการอื่น

## การจองยอดและการบันทึกการเงิน

เก็บใน MySQL ตาราง `transfer_instructions` ใช้หนึ่งรายการต่อบิล พร้อม snapshot บิล ผู้พัก บัญชีรับ และยอดจริง มี unique index ของยอดที่ยังจองหรืออยู่ในช่วงพักหลังชำระ พร้อม transaction และ global allocation lock ป้องกันการสร้างพร้อมกันคนละ process

ยอดบิลและ `payments.amount` ยังคงเป็นยอดหนี้เดิม ส่วนต่างสตางค์/ยอดโอนเก็บแยกไว้ในคำสั่งโอนและผลตรวจสลิปเมื่อยืนยัน ไม่แอบแก้ค่าห้อง ค่าน้ำ ค่าไฟ หรือยอดเอกสารที่ออกแล้ว ส่วนต่างไม่ได้ถูกคืนเงินหรือหักบิลเดือนถัดไปอัตโนมัติ ผู้ดูแลต้องกำหนดวิธีกระทบยอดส่วนต่างนี้

เมื่อตรวจสลิปของบิลที่จองแล้ว โค้ดส่งยอดโอนรวมสตางค์ให้ผู้ให้บริการตรวจ และตรวจ fingerprint การตั้งค่าอีกครั้งก่อน finalization หากบัญชี/ยอดไม่ตรงจะไม่ทำเครื่องหมายชำระแล้ว บิลเก่าที่ไม่มีคำสั่งโอนใช้การตรวจยอดเดิม

จำกัด 99 ตัวเลือกต่อยอดตั้งต้นเดียวกัน และอาจเหลือน้อยกว่านั้นเมื่อชนช่วงยอดของบิลอื่น หากครบจะแจ้งให้ติดต่อผู้ดูแล ไม่สุ่มวนไม่จบ ไม่ใช้ยอดซ้ำ และไม่บวกเกิน 0.99 บาทเพื่อฝืนผ่าน

คำสั่งที่ยังไม่ชำระไม่หมดอายุเอง หลังระบบยืนยันชำระจะพักยอดไว้อีก 7 วัน จากนั้นการจองครั้งต่อไปจึงคืนช่องยอดได้ ประวัติคำสั่งเดิมยังอยู่ ไม่รับรองยอดไม่ซ้ำตลอดประวัติทุกปี รูป QR เก่าอาจถูกใช้โอนภายหลังได้ จึงต้องตรวจเวลา บัญชีผู้รับ และเลขอ้างอิงเงินจริงด้วยเสมอ ห้ามจับคู่หรืออนุมัติจากยอดอย่างเดียว

การล็อกนี้คือการล็อกยอดในระบบและใส่ยอดใน QR ไม่ใช่อำนาจห้ามคนโอนเองด้วยยอดอื่นหรือใช้ภาพ QR ซ้ำจากแอปธนาคาร ถ้าโอนไปแล้วให้ตรวจรายการเดิมก่อน ไม่ออกยอดใหม่หรือสั่งให้โอนซ้ำอัตโนมัติ

## อัปเกรดฐานข้อมูลเดิมก่อนใช้ฟีเจอร์

ต้องใช้ migration `database/migrations/016_unique_transfer_instructions.sql` หลัง schema ถึง 015 โดยสำรอง MySQL และทดสอบกับสำเนาฐานของตนก่อน เลือกฐานของโปรเจกต์ใน phpMyAdmin แล้ว Import ไฟล์ 016 ด้วยบัญชีที่มีสิทธิ์สร้างตาราง/trigger ในช่วงบำรุงรักษา อย่า Import `database/install.sql` ทับฐานเดิม และอย่าใช้ force เพื่อข้าม SQL error

ไฟล์ 016 เพิ่มตารางและ trigger ของคำสั่งโอน ไม่เขียนทับข้อมูลห้อง บิล หรือ payment เดิม `database/transfer_instructions.sql` เป็น canonical source; script build สร้างสำเนา migration/fresh installer ให้ตรงกัน ข้อมูลใหม่เก็บใน MySQL ไม่ใช่ RAM หรือไฟล์ชั่วคราวของเว็บ

หลังนำเข้า 016 ให้ตรวจด้วยบัญชี schema owner: `php scripts/check_requirements.php --db --schema-audit` และตรวจ QR ของบิลทดสอบบน staging ก่อนเปิดรับจริง การอัปเดตโค้ดอย่างเดียวไม่สร้างตารางให้บน Railway หากยังไม่มีตาราง เว็บจะไม่เดายอดและจะแจ้งว่าต้องเปิดระบบจองยอดก่อน ส่วนข้อมูลบิลเดิมยังอยู่

หากมีภาพ QR เดิมหรือโอนไปแล้วก่อนเปลี่ยนรุ่น ให้ตรวจเงินเข้ารายการเดิมก่อนสร้างคำสั่งโอนใหม่ อย่าให้ลูกบ้านโอนซ้ำเพื่อปรับยอดให้เข้ารุ่นใหม่

## ผลทดสอบและขอบเขต

PHP unit/contract 125 ผ่าน, JavaScript 153 ผ่าน, PHP syntax 89 ไฟล์ผ่าน และ JavaScript syntax 4 ไฟล์ผ่าน พร้อม LINE offline, billing CLI, worker contract, shell syntax และ generated SQL consistency

MySQL แยก 15 ชุดผ่านและ schema audit ผ่าน ชุด transfer ใหม่ 10 กลุ่มครอบคลุมสร้าง QR โดยไม่มี slip provider, เปิดใหม่ได้ยอดเดิม, สิทธิ์ของบิล, LINE reference, เปลี่ยนบัญชี, ความไม่เปลี่ยนแปลงของ snapshot, 99 ยอดไม่ซ้ำและปฏิเสธยอดที่ 100, เงินต้นมีสตางค์, การจองจากหลาย process และยอดที่ส่งให้ตัวตรวจสลิปต้องเป็นยอดโอนที่จองไว้

Edge headless 89 กรณีผ่าน: 79 กรณีเดิมและ 10 กรณี QR/LINE fallback ใช้หน้า HTML/CSS/JavaScript จริงกับ API จำลอง ตรวจขนาดจอ 320/390/768/1366 ปิดเครือข่ายภายนอก ไม่ส่งภาพเข้าบัญชี LINE จริง ไม่ใช้ API key จริง และไม่โอนเงิน

ยังไม่ได้ทดสอบ migration 016 กับสำเนาฐาน production ของผู้ใช้ หรือยืนยันการรับสลิปยอดบวกสตางค์กับผู้ให้บริการจริงแบบครบเส้นทาง และยังไม่ได้ยืนยันการใช้งานบน Safari/iPhone จริง จึงไม่ควรถือผล unit/integration/browser ว่าเป็นหลักฐานว่ารับเงินจริงแล้ว

ไม่ได้แก้ `.env`, APP_KEY, บัญชีรับเงินจริง หรือข้อมูล production ไม่รัน migration บนฐานจริง ไม่เพิ่มปุ่ม manual-paid และไม่ใช้ LINE message/image event เป็นคำสั่งเปลี่ยนบิลเป็น paid สำเนาก่อนแก้และหลักฐานตรวจอยู่ใน `storage/logs/unique-transfer-20260921/` ซึ่งไม่อยู่ใน commit

แก้ gate ของบัญชี runtime ให้รับ schema 22 ตาราง และเพิ่ม regression เปรียบเทียบจำนวนตาราง canonical กับ provisioning/bootstrap/CI หลัง CI แรกล้มเหลวเพราะยังตรวจ 21 ตาราง ไม่ได้ผ่อนปรนสิทธิ์ฐานข้อมูลหรือข้ามการตรวจใด
