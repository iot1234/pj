# ตรวจฟีเจอร์และเส้นทางแก้ไขข้อผิดพลาด — 22 กันยายน 2026

ขอบเขตเฉพาะ PHP/MySQL ใน repository นี้ ต่อจาก `PAYMENT_AUDIT_2026-09-21.md`
ตรวจฟีเจอร์หลักด้วย regression tests, MySQL จริงแบบแยกฐานทดสอบ และ Edge headless
ไม่ได้แก้ข้อมูล production หรืออ้างว่าทดสอบทุกสภาพแวดล้อม/ข้อผิดพลาดที่เป็นไปได้

## สิ่งที่ปรับปรุง

- เพิ่มคำแนะนำในฟอร์มเมื่อผิดพลาด พร้อมปุ่มไปแก้ช่องที่ผิดหรือหน้าที่เกี่ยวข้อง
  เช่น ย้ายออกติดบิลค้าง → ใบแจ้งหนี้, ขาดเลขเริ่มต้น → ผู้พักอาศัย,
  มิเตอร์ขาดงวด → จดมิเตอร์ และตั้งค่าบริการไม่ครบ → หน้าตั้งค่า
  ผู้ดูแลทั่วไป/ผู้พักไม่ได้ปุ่มไปหน้าของเจ้าของที่ไม่มีสิทธิ์
- การนำทางออกจาก dialog ต้องให้ผู้ใช้ยืนยันก่อน ไม่ส่งคำสั่งบันทึก ออกบิล
  ย้ายผู้พัก หรืออนุมัติชำระเงินให้อัตโนมัติ คำแนะนำเตือนให้เก็บข้อมูลที่ยังไม่บันทึก
- รายการที่โหลดผิดพลาดมีปุ่มลองโหลดหน้านั้นใหม่ แยกจากการส่งรายการซ้ำ
  ผลลัพธ์ไม่ครบหรือการตอบกลับจากคำขอเก่าจะไม่เปิดให้ใช้รายการเก่าผิดพลาด
- ป้องกันกดซ้ำทั้งฟอร์มยกเลิกจอง รับเข้าพัก ย้ายออก ปิดรายการชำระ
  และคำยืนยันการจอง/ปิดบัญชีผู้ดูแล ตรวจรายการซ้ำหลังปิดกล่องยืนยัน
  ล็อกช่องกรอกระหว่างส่ง และไม่ให้การโหลดข้อมูลของคำขอเก่าปลดล็อกคำขอใหม่
- เมื่อรับเข้าพักพบผู้พักเดิม ช่องยืนยันเชื่อมประวัติยังเปิดให้แก้ไขได้หลังปลดล็อก
  ไม่ถูกการคืนค่า disabled ทับกลับจนดำเนินการต่อไม่ได้
- คงค่าที่กรอกและข้อความผิดพลาดไว้เมื่อบันทึกไม่ผ่าน; หากไม่ทราบผลการเขียน
  ให้ตรวจสถานะล่าสุดก่อนส่งอีกครั้ง ไม่ retry การเขียนโดยอัตโนมัติ

## QR, ยอดล็อก และ LINE

- การเปิด QR แยกจากบริการตรวจสลิป ตรวจ readiness เฉพาะ credential ของ provider
  ที่เลือก หาก key ที่ไม่ได้ใช้หรือ key ที่เข้ารหัสเสียอ่านไม่ได้ จะไม่ทำให้ QR หยุดทำงาน
  แต่ยังปิดการตรวจสลิปที่ไม่พร้อมไว้ ไม่ข้ามการตรวจหลักฐาน
- เพิ่มการทดสอบ provider ปิด/เปิด, credential เสีย, LINE ยังไม่ตั้งค่า,
  ยอดฐานมีทศนิยมทับช่วงกัน และ unique index ป้องกันยอดชนกัน
- การจองเดิมเพิ่ม 0.01–0.99 บาทและคงยอดเมื่อเปิดซ้ำ บันทึกส่วนต่างแยกจากยอดบิล
  ไม่ใช้ยอดซ้ำกับรายการที่ยังจองอยู่ ตัวอย่างการทดสอบสามห้องฐาน 100.00 บาท
  ได้ยอดต่างกันทั้งหมด; ตรวจ TLV/CRC ของ payload ตรงยอดและบัญชีที่ตั้งไว้
- ฐานยอดเดียวกันมีได้สูงสุด 99 ช่องสตางค์ และอาจเหลือน้อยลงหากทับช่วงยอดอื่น
  เมื่อช่องเต็มต้องหยุดพร้อมคำแนะนำ ไม่ปัดเศษ ไม่ใช้ยอดซ้ำ ไม่ปล่อย QR ที่ไม่ถูกต้อง
  รายการยังไม่ชำระไม่ปล่อยยอดจองเอง ส่วน settled เก็บช่วงป้องกันซ้ำตามนโยบายเดิม
- เมื่อปิดตรวจสลิปหรือสลิปรอตรวจ/ตรวจไม่สำเร็จ แสดงทางไป LINE Bot เดียวของหอพัก
  พร้อมเลขบิล ห้อง และยอด หากไม่มี LINE ที่ถูกต้องให้ติดต่อสำนักงาน ไม่สร้างลิงก์ปลอม
- ส่งข้อความพร้อมเลขบิลและแนบรูปในแชต LINE เป็นการส่งหลักฐานให้ผู้ดูแลตรวจ
  **ไม่ใช่การนำรูปเข้าระบบหรือเปลี่ยนบิลเป็น paid อัตโนมัติ** ไม่เพิ่ม API อนุมัติเงินด้วยมือ
  บิลจะเป็น paid เมื่อผ่านกระบวนการตรวจสลิปที่รองรับเท่านั้น

Browser integration ใช้หน้าเว็บ PHP และ session/ฐาน MySQL จริง ไม่ mock API การชำระ:

- ผู้พักสามห้องสร้าง QR ได้ขณะปิด provider, ยอดไม่ซ้ำ และ reload ได้ยอดเดิม
- QR payload มีบัญชี/ยอด/สกุลเงิน/CRC ถูกต้อง, canvas แสดงได้ และ LINE มีเลขบิลกับยอด

- ตั้งค่าผู้ให้บริการไม่ครบถูกปฏิเสธโดย QR ยังใช้ได้ และแก้ LINE ผ่านหน้าชำระไม่ได้
- ย้ายออกขณะมีบิลค้างถูกปฏิเสธ แล้วกดคำแนะนำไปหน้าบิลได้ โดยไม่มีการย้ายออกหรือตัดบิล
- หน้า admin ทั้ง 11 หน้าโหลดผ่าน API จริงโดยไม่มี read error
- จำลอง GET รายการผู้ดูแลล้มเหลว: ล้างรายการเก่า ปุ่มลองใหม่อ่านข้อมูลจริงกลับได้
- ไม่มี JavaScript runtime error

## ก่อนใช้งานจริง

1. สำรองฐานข้อมูล/ไฟล์หลักฐาน และตรวจ schema ของระบบที่จะ deploy ให้ตรงกับรุ่นนี้
   รวม migration ระบบจองยอดที่มีอยู่เดิม ไม่แก้ schema หรือข้อมูลการเงินด้วยการเดา
2. ตั้ง PromptPay และตรวจชื่อผู้รับในแอปธนาคารบน staging; QR ไม่ต้องเปิด provider
3. เชื่อม LINE ในหน้า “บัญชี LINE OA” เพียงบัญชีเดียว ทดสอบลิงก์และ webhook จริง
4. หากต้องการตัดบิลอัตโนมัติ ให้ตั้ง provider/บัญชีรับเงิน/โควตา และทดสอบสลิปผ่านเว็บ
5. ทดสอบการโอนและการตอบกลับ provider จริงด้วยขั้นตอนที่เจ้าของอนุมัติแยกต่างหาก

การตรวจครั้งนี้ไม่เรียกผู้ให้บริการตรวจสลิปจริง ไม่ส่งข้อความ LINE จริง และไม่โอนเงินจริง
จึงยังไม่ยืนยัน credentials, โควตา, delivery ของ LINE หรือการรับเงินของบัญชี production
