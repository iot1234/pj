# ผลตรวจ LINE OA / การผูกห้อง / คำสั่งบอท — 2026-09-15

รอบนี้ขยายจากงานผูกผู้พักเดิม ตามคำขอให้แอดมินจัดการ LINE เหมือนหน้าบัญชี OA และหน้าผูกห้องใน `newap` ระบบอ้างอิงถูกอ่านอย่างเดียว งานอยู่ใน `php-mysql` คู่มือใช้งานและการอัปเกรด: [LINE_BINDING.md](LINE_BINDING.md)

## พฤติกรรมที่รองรับ

- Admin และ Owner เพิ่ม/แก้/ปิด/ลบหลาย OA ตั้ง token/secret/Basic ID เลือก OA หลัก ทดสอบ bot identity หมุน webhook URL และดูเวลารับ webhook
- ออกรหัส 1–30 วัน ดูรหัสค้างซ้ำ เพิ่มหลายบัญชีต่อห้อง ยกเลิกเฉพาะคีย์/บัญชี/ทั้งหมด บล็อกพร้อมเหตุผล และปลดบล็อก
- บอทผูกจากข้อความที่เซ็นถูกต้องของ OA ที่ระบุ ตอบชื่อ/ห้อง และคำสั่งเมนู/สถานะ/บิล
- ส่งบิลแยกตามบัญชี พร้อมสรุปผลหนึ่งแถวต่อบิล ไม่ส่งให้บัญชีที่ถูกยกเลิกหรือบิลที่มีสลิปรอตรวจ
- คีย์ OWNER/ADMIN สำหรับผู้รับแจ้งเตือน ตั้งชื่อ เปิด/ปิด ยกเลิก และปิดเสียงรายหมวด มีเหตุการณ์จากการจอง เข้าพัก/ย้ายออก บิล ชำระเงิน และออกสิทธิ์ใหม่
- Legacy OA 0 และคีย์จากโปรไฟล์เดิมยังรองรับ การเปลี่ยน OA หลักไม่ย้ายบัญชีหรือคิวเดิม

## ประเด็นที่พบและแก้

- ป้องกันบิลซ้ำในรายการเมื่อมีหลายผู้รับ และแสดงผลส่งไม่ครบให้เห็น แยกคิวของบัญชีที่ผูกเพิ่มโดยไม่ส่งซ้ำให้ผู้รับเดิม
- ป้องกัน token ของ OA อื่นแทนบัญชีที่ผูกอยู่ ตรึง OA/ผู้รับ/payload/retry UUID และตรวจ signature/destination ก่อนใช้รหัส
- อ่านและตรวจสิทธิ์อีกครั้งภายใต้ registry/resident lock ก่อนส่งชื่อ ห้อง หรือบิล ถือ bill/payment locks ระหว่างการยอมรับข้อความเพื่อไม่ส่งคำสั่งให้ชำระซ้ำหลังมีสลิป
- ถือ registry lock ครอบคลุม bulk enqueue และ audit commit ป้องกันการรอ lock สวนกันกับ worker
- ลบ OA ยกเลิกคีย์/บัญชี/ผู้รับแจ้งเตือนเฉพาะ OA นั้น เก็บประวัติ และเพิ่ม OA เดิมใหม่ได้โดยไม่คืนสิทธิ์เก่า การผูกและคิวแจ้งเตือนแอดมิน commit/rollback พร้อมกัน
- คีย์ OWNER ที่ปิดใช้แล้วใช้แทนเจ้าของเดิมไม่ได้ ตรวจค่าเปิด/ปิดและสมาชิกหมวดแจ้งเตือนก่อนบันทึก
- การเปลี่ยนเบอร์ ออกสิทธิ์ใหม่ ย้ายออก และปุ่ม unlink เดิมยกเลิกบัญชีใหม่/คีย์ค้างครบ
- หน้าผู้พักและกล่องแอดมินเดิมแสดงบัญชีที่ผูกหลายรายการแม้ไม่มี hint เดี่ยว ปิดสร้างรหัสเมื่อถูกบล็อก และล็อกฟอร์มจนโหลดข้อมูลครั้งแรกเสร็จเพื่อไม่ทับข้อมูลที่กรอก
- ดู/สร้าง QR และลิงก์เฉพาะรหัสที่ตรงกันและยังมีอายุ ป้องกันผลตอบกลับเก่าข้ามห้อง รักษาข้อมูลที่กำลังกรอกขณะ refresh และปรับ dialog ให้พอดีมือถือ

## ขอบเขตของหลักฐาน

LINE bot-info, reply และ push ถูกแทนด้วย transport จำลองใน process สำหรับ QA ไม่มีข้อความถูกส่งถึง LINE จริง ทดสอบว่าคีย์ถูกจับคู่กับ OA, ลายเซ็นและสิทธิ์ถูกตรวจ และเส้นทาง retry/rollback ทำงาน ไม่ใช่หลักฐานว่า credentials ของ production หรือการตั้งค่าบน LINE Developers พร้อมแล้ว

ยังไม่ได้ deploy, migrate ฐานจริง, ทดสอบผ่านมือถือกับ LINE OA จริง หรือรัน Docker CI บนเครื่องนี้ ต้องทำ migration 014 และตรวจรับ LINE จริงก่อนเปิดใช้ ภาพสลิปผ่านแชตโดยตรงและ flow ผูกผู้จองก่อนเข้าพักยังไม่รองรับ หมวด maintenance/system มีตัวเลือกปิดเสียงแต่ระบบนี้ยังไม่มีเหตุการณ์ต้นทาง
