# LINE OA การผูกห้อง และคำสั่งบอท

ระบบ PHP/MySQL ใช้ LINE Bot หลักหนึ่งบัญชีต่อหอพัก (OA 0) รองรับผู้รับหลายบัญชีต่อห้อง และหน้าจัดการสำหรับ **admin และ owner** สิทธิ์ตั้งค่าการเงินและจัดการผู้ดูแลยังใช้สิทธิ์เดิม

## ตั้งค่า LINE OA

หลังบันทึกหน้าสถานะจะแสดงต่อทันที กด **ตรวจการเชื่อมต่อจริง** เพื่ออ่าน Token, URL และ Use webhook จาก LINE ระบบแยกผลตรวจปัจจุบันออกจากประวัติที่เคยรับ Webhook ไม่มีการค้างรอโดยไม่สิ้นสุด และมีปุ่มตรวจค่าที่บันทึกเมื่อการตอบกลับขาดหาย ดู [รายละเอียดการแก้ค้างและสถานะ](LINE_CONNECTION_REVIEW_2026-09-20.md)


เปิดหลังบ้าน → **บัญชี LINE OA** (`/admin#line-oas`)

1. กด **ตั้งค่า LINE Bot** ระบบเปิดบอทหลัก OA 0 ให้ ไม่ต้องเลือกหรือสร้าง OA เพิ่ม
2. กรอกเพียง **Channel access token** และ **Channel secret** ของ OA เดียวกัน แล้วบันทึก ระบบตรวจตัวตนและดึงชื่อ/Basic ID จาก LINE พร้อมสร้างลิงก์เพิ่มเพื่อนและ Webhook URL ให้ ชื่อ Basic ID และลิงก์แสดงเป็นข้อมูลอ่านอย่างเดียว โดยชื่อบัญชีใช้ชื่อที่ LINE ส่งกลับ
3. หลังบันทึก ระบบเปิดหน้า Webhook ให้ทันที คัดลอก URL ของบัญชีนั้นไปตั้งใน LINE Developers เปิด **Use webhook**, **Webhook redelivery** แล้วกด **Verify** หน้าสถานะจะตรวจผลให้อัตโนมัติ
4. ต้องการผูกผู้รับหลายคน ให้เพิ่มรหัสผูกให้แต่ละคนในหน้า **ผูก LINE ห้อง** ไม่ต้องเพิ่มบอท

การทดสอบ Token ตรวจเฉพาะตัวตน OA และไม่ยืนยัน Channel secret จนกว่าจะได้รับ webhook ที่ลายเซ็นถูกต้อง หน้าจอแยกสถานะการตั้งค่า ตัวตน และ webhook; การเปลี่ยน Secret จะล้างประวัติยืนยัน webhook และต้อง Verify ใหม่ สถานะนี้เป็นหลักฐานว่าเคยรับ webhook สำเร็จ ไม่ใช่การตรวจว่า Use webhook ยังเปิดอยู่ตลอดเวลา ระบบยังอนุญาตเตรียมรหัสล่วงหน้าได้ แต่ควร Verify และทดสอบแชตจริงก่อนส่งรหัสให้ผู้พัก

สามารถบันทึกร่างที่ปิดใช้งานและยังไม่มีคีย์ได้ โดยไม่ต้องกรอกชื่อหรือรหัสภายใน หากกดทดสอบ Token ของร่าง ระบบจะบันทึก Basic ID ที่ดึงมาโดยไม่เปิดใช้งานบัญชี

เปลี่ยนคีย์ ปิดใช้งาน ทดสอบ ตรวจเวลารับ webhook ล่าสุด และหมุน URL ได้ แต่ไม่เปิดให้ลบบอทหรือเปลี่ยนไปใช้บอทอื่น ช่องคีย์ว่างรักษาค่าเดิม การเลือกล้างคีย์ต้องยืนยันและระบบจะปิดใช้งานบอทในคำขอเดียวกันก่อนล้าง

Token ใหม่ต้องเป็นของบอทเดิม ระบบตรวจ provider identity เพื่อรักษาบัญชีผู้พัก การปิดใช้งานหยุดการส่งโดยไม่ลบประวัติ เปิดใหม่ไม่คืนบัญชีที่ถูกยกเลิก การหมุน URL ทำให้ URL เดิมใช้ไม่ได้ ต้องนำ URL ใหม่ไปตั้งที่ LINE

**OA 0** ใช้ค่า LINE เดิมจาก integration settings เพื่อรองรับผู้เช่าที่ผูกก่อนอัปเกรด บัญชีเหล่านั้นคงส่งผ่าน OA 0 โดยไม่มีตัวเลือกบอทอื่น URL เดิม `/api/webhooks/line` ใช้ได้จนกว่าจะหมุน route ของ OA 0 ให้จัดการคีย์ผ่านหน้า OA เท่านั้น API settings เดิมปฏิเสธการแก้คีย์ LINE เพื่อไม่ให้ข้ามการตรวจว่าเป็น OA เดิม

## สร้างคีย์และจัดการห้อง

เปิด **ผูก LINE ห้อง** (`/admin#line-bindings`) ค้นหาชื่อ/ห้อง/โทรศัพท์ และกรองสถานะได้

1. เลือกผู้พักที่กำลังเข้าพัก → ระบบเลือกบอทหลักให้ → กำหนดอายุคีย์ 1–30 วัน (เริ่มต้น 7 วัน)
2. เลือกสร้างแทนคีย์ที่ค้าง หรือเพิ่มคีย์อีกชุดเพื่อผูกหลายบัญชีกับห้องเดียว
3. คัดลอกรหัส หรือใช้ **เปิด LINE พร้อมรหัส** / QR ให้ผู้รับกดส่ง `BIND-…` ในแชตส่วนตัวของ OA ที่ระบุ
4. บอทผูกบัญชีและตอบชื่อ/ห้อง หน้ารายละเอียดแสดงจำนวนบัญชีและประวัติ

แอดมินดูรหัสที่ยังไม่หมดอายุซ้ำได้ ยกเลิกเฉพาะคีย์ เฉพาะบัญชี หรือทั้งหมดได้ หากผูกผิดให้ยกเลิกบัญชีนั้นและสร้างคีย์ใหม่ บล็อกการผูกพร้อมเหตุผลได้สูงสุด 500 ตัวอักษร การปลดบล็อกเปิดให้สร้างคีย์ใหม่ ไม่คืนการผูกเก่า

หนึ่ง LINE User ID ใน OA เดียวกันผูกกับผู้พักปัจจุบันได้รายเดียว หนึ่งห้องผูกผู้รับหลายบัญชีผ่านบอทหลักเดียวกันได้ ไม่อนุญาตกรอก LINE User ID ตรงเพื่อข้ามการยืนยัน

ผู้พักยังสร้างรหัสผ่านหน้าโปรไฟล์ได้ โดย flow เดิมใช้ OA 0 และอายุ 10 นาที แอดมินออกคีย์เพิ่มให้ผู้รับคนอื่นได้จากหน้าผูกห้อง ปุ่มยกเลิก LINE ในโปรไฟล์หรือกล่องผู้พักเดิมยกเลิกทุกบัญชีและคีย์ค้างของผู้พัก

## คำสั่งผู้พัก

| ข้อความ | ผล |
|---|---|
| `เมนู`, `ช่วย`, `เริ่ม`, `help`, `start`, `menu` | วิธีใช้และลิงก์พอร์ทัล |
| `สถานะ`, `ห้อง`, `status`, `room` | ยืนยันการผูก ชื่อและห้องปัจจุบัน |
| `บิล`, `bill`, `bills`, `invoice` | บิลล่าสุดไม่เกิน 3 รายการ พร้อมยอด กำหนดชำระ และผลตรวจสลิป |
| `BIND-…` | ยืนยันการผูกด้วยรหัสที่ระบบสร้าง |

รองรับตัวพิมพ์เล็ก/ใหญ่และอักขระที่ติดจากการคัดลอก รับเฉพาะแชตส่วนตัว คำสั่งห้อง/บิลตรวจหลักฐานและสิทธิ์ปัจจุบันก่อนส่ง ข้อความคุยทั่วไปไม่เรียกบอท

เมื่อชำระแล้วหรือมีสลิปกำลังตรวจ บอทแจ้งไม่ให้โอนซ้ำ ลิงก์รายละเอียดเปิดพอร์ทัลที่ต้องเข้าสู่ระบบ ภาพสลิปส่งผ่านพอร์ทัล การรับสลิปผ่านแชตโดยตรงยังไม่รองรับ

## ผู้รับแจ้งเตือนของแอดมิน

ในหน้าบัญชี OA สร้างคีย์ผู้รับแบบเจ้าของ (`OWNER-…`, 5 นาที) หรือเจ้าหน้าที่ (`ADMIN-…`, 10 นาที) จากนั้นให้ผู้รับส่งคีย์เข้าบอทหลักของหอพัก บอทแจ้งผลยืนยัน แก้ชื่อผู้รับ เปิด/ปิด ยกเลิก และปิดเสียงรายหมวดได้

เมื่อคีย์เจ้าของใหม่ถูกยืนยัน จึงแทนเจ้าของเดิมของ OA นั้น คีย์หมดอายุ/ปิดใช้งาน/ผิด OA ไม่สามารถแทนเจ้าของเดิมได้ ผู้รับซ้ำใน OA เดียวกันถูกส่งเพียงครั้งเดียวต่อเหตุการณ์

รองรับหมวด booking, payment, billing, tenancy, maintenance, security, system ตามโครงสร้างอ้างอิง เหตุการณ์ที่เชื่อมแล้วคือการจอง/ยืนยัน/ยกเลิก เข้าพัก/ย้ายออก ผูก LINE สร้างบิล รับและตรวจสลิป และออกสิทธิ์ผู้พักใหม่ หมวด maintenance/system สงวนไว้สำหรับเหตุการณ์ที่ระบบนี้ยังไม่มี ข้อความแอดมินเป็นสถานะทั่วไปพร้อมลิงก์เข้าหลังบ้าน ไม่ใส่ข้อมูลส่วนตัวหรือรหัสผูก

## คิวส่งและการป้องกันข้อผิดพลาด

- ส่งบิลแยกตามบัญชีที่ยืนยันแล้ว แต่แสดงบิลหนึ่งแถวพร้อมจำนวนรอส่ง/ส่งแล้ว/ล้มเหลว บัญชีที่ผูกเพิ่มภายหลังรับบิลได้โดยไม่ส่งซ้ำให้คนเดิม
- คิวตรึง OA ผู้รับ payload และ retry UUID การ retry ใช้ข้อมูลเดิมและตรวจบัญชี/สิทธิ์/สถานะบิลล่าสุดก่อนส่ง
- หยุดส่งบิลเมื่อมีสลิปกำลังตรวจหรือชำระแล้ว บัญชีถูกยกเลิก ถูกบล็อก ผู้พักเปลี่ยนเบอร์ ออกสิทธิ์ใหม่ หรือย้ายออก จะไม่ได้ข้อมูลของสิทธิ์เดิมต่อ
- ตรวจ webhook จาก raw body กับ secret ของ OA นั้น และตรวจ destination กับ bot identity ที่ยืนยันไว้ แยกการกัน webhook ซ้ำตาม OA
- คีย์สุ่ม 128 บิต ค้นหาด้วย HMAC และเข้ารหัสคีย์แอดมินที่ต้องเปิดดูซ้ำ คีย์ผูกจากโปรไฟล์เดิมเก็บเฉพาะ HMAC ไม่บันทึกคีย์หรือ LINE ID ดิบใน audit
- การผูก/ยกเลิก/แก้ OA และหลักฐาน audit อยู่ใน transaction เดียวกัน ตรวจสิทธิ์ซ้ำภายใต้ lock ก่อนส่งข้อมูลส่วนตัว
- worker เดิมส่งทั้งบิลและแจ้งเตือน ต้องมี worker ทำงาน ข้อความแจ้งเตือนค้างเกิน 24 ชั่วโมงถูกยกเลิก และตรวจผู้รับ/การปิดเสียงอีกครั้งตอนส่ง

อ้างอิง LINE: [ตรวจลายเซ็น webhook](https://developers.line.biz/en/docs/messaging-api/verify-webhook-signature/) และ [retry request](https://developers.line.biz/en/docs/messaging-api/retrying-api-request/)

## การอัปเกรดและตรวจรับ

ฐานใหม่ใช้ `schema.sql` + `defaults.sql` หรือ `install.sql` ซึ่งรวมโครงสร้างปัจจุบันแล้ว ฐานเดิมต้องผ่าน migration ถึง `013` แล้วหยุด traffic/worker/cron สำรองฐานและทดสอบ restore รัน `014_line_platform.sql` ตามด้วย `015_pending_occupancy_opening_readings.sql` ก่อนเปิด source นี้ ตรวจ LINE ด้วย `php scripts/check_line_platform_schema.php` และตรวจทั้งระบบด้วย `php scripts/check_requirements.php --db --strict --production` พร้อม schema audit ตาม [คู่มือ SQL](SQL_SETUP.md) การตรวจ LINE อย่างเดียวไม่ยืนยันว่า migration `015` ครบ ห้ามนำ `install.sql` ไปทับฐานที่มีข้อมูล

Fresh schema มี 21 ตาราง 23 triggers และ 116 CHECK constraints ค่า OA 0 ไม่มีคีย์ลับจำลอง Migration ไม่ย้าย LINE ID เดิมเข้า OA ใหม่และไม่ใส่ provider credential

ผลตรวจและข้อจำกัดอยู่ใน [รายงาน QA](LINE_QA_2026-09-15.md) ต้องตรวจรับกับ LINE OA จริงและมือถือก่อนเปิดให้ผู้พักใช้งาน รอบนี้ทดสอบด้วย provider จำลองและฐานแยก ไม่มีการ deploy หรือแก้ฐานจริง

**ก่อนอัปเกรดฐานที่เคยใช้หลาย OA:** source นี้ใช้งาน OA 0 เท่านั้น ต้องตรวจบัญชี การผูก และคิวที่อ้าง OA ID อื่นก่อน deploy ไม่มีการย้ายผู้รับ ลบประวัติ หรือเปลี่ยน Token ข้ามบอทให้อัตโนมัติ สำรองและกำหนดแผนย้ายอย่างชัดเจนก่อนใช้กับฐานดังกล่าว
