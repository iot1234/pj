# ตรวจฟีเจอร์อื่นและการทำงานร่วมกัน — 22 กันยายน 2026

ตรวจต่อจาก `FEATURE_AUDIT_2026-09-22.md` เฉพาะโปรเจกต์ PHP/MySQL นี้
รอบนี้มุ่งห้องพัก การจอง รับเข้าพัก ผู้พัก มิเตอร์ บิล สิทธิ์ผู้ดูแล และการเพิกถอน LINE
ไม่เปลี่ยนนโยบายเข้าสู่ระบบด้วยเบอร์ ไม่เปลี่ยน schema และไม่แก้ข้อมูล production

## ปัญหาที่พบและแก้

1. **รายการผู้พักเก่ายังกดได้ระหว่างโหลด:** ล้างข้อมูล/แถวเก่าทันที ล็อกตาราง
   ไม่ให้การค้นหาหรือผลตอบกลับเก่าชุบรายการกลับมา ทั้งห้องพักและผู้พักต้องได้
   array ที่มี ID ถูกต้องและไม่ซ้ำก่อนเปิด actions; โหลดไม่ได้มีปุ่มลองใหม่
2. **ฟอร์มรับเข้าพักอาจใช้ cache ห้องเก่า:** โหลดห้องใหม่ก่อนเปิดทุกครั้ง
   ไม่เปิดฟอร์มถ้าโหลดไม่สำเร็จ ไม่ให้คำขอเปิดก่อนหน้าทับฟอร์มที่เปิดใหม่
   และไม่ reset ร่าง/เปลี่ยน idempotency key ขณะฟอร์มกำลังเปิดหรือส่งอยู่
3. **เพิ่ม/แก้ผู้พักกดซ้ำหรือแก้ช่องระหว่างส่ง:** ใช้ล็อกฟอร์มและ dialog เดียวกัน
   ตั้งแต่ก่อนส่งหรือก่อนถามยืนยันเปลี่ยนเบอร์ ปลดล็อกเพียงครั้งเดียว
   ผลโหลดหลังบันทึกเก่าไม่ปลดล็อกคำขอใหม่
4. **ยืนยันเปลี่ยนเบอร์อาศัย cache รายชื่อ:** เก็บเบอร์เดิมตอนเปิดฟอร์ม
   แม้รายการถูกโหลดใหม่/ล้าง cache ก็ยังถามยืนยัน และบอกว่า LINE เดิมถูกเพิกถอนด้วย
   เมื่อปฏิเสธหรือบันทึกผิดพลาดยังเก็บค่าที่กรอกไว้
5. **เชื่อมผู้พักเก่าหรือห้องถูกจองระหว่างกรอก:** คืนสถานะช่องก่อนเปิด checkbox
   ยืนยันบุคคลเดิม จึงไม่ถูก finally ปิดกลับ; กรณีห้องไม่ว่างโหลดห้องใหม่
   โดยคงข้อมูลผู้พักและคำขอเดิมให้แก้ไข ไม่สร้างคำขอใหม่อัตโนมัติ
6. **ลบห้องจากข้อมูลเก่าหรือกดซ้ำ:** ล็อกระหว่างยืนยัน/ส่ง ตรวจว่าเป็น row เดิม
   หลังผู้ใช้ยืนยัน และอ่านสถานะกลับหากผลไม่แน่นอน ไม่ retry DELETE อัตโนมัติ
7. **เข้าสู่ระบบผู้ดูแลซ้ำ:** ล็อก credentials และปุ่มระหว่างส่ง ปลดเฉพาะเมื่อผิดพลาด
   ความสำเร็จรอเปลี่ยนหน้าโดยไม่เปิดให้ส่งรอบซ้อน
8. **บันทึก profile ลูกบ้านซ้ำ/ผลโหลดทับชื่อใหม่:** ใช้ in-flight flag และเพิ่ม revision
   หลังจบการบันทึก จึงกันทั้งผลอ่านที่เริ่มก่อนบันทึกและระหว่างบันทึก แม้ผลอ่านมาทีหลัง
9. เพิ่มคำแนะนำกรณีเลขห้องซ้ำ ห้องใช้งานอยู่ เบอร์มีการจอง สถานะการจองเปลี่ยน
   ตัวอย่างบิลเก่า และการปิด/ลดสิทธิ์เจ้าของ โดยไม่เสนอวิธีข้ามข้อห้าม

## การทดสอบข้ามฟีเจอร์ใหม่

`tests/operations_mysql.php` รันกับ MySQL จริง ฐานใหม่ และบัญชี runtime
SELECT/INSERT/UPDATE; เพิ่มใน CI แล้ว **14 กลุ่มผ่าน**:

- เลขห้อง normalize/ซ้ำ และข้อมูลผิดไม่แก้ข้อมูลเพียงบางส่วน
- replay จองไม่สร้างซ้ำ เบอร์เดียวจองคนละห้องไม่ได้ ห้องจองอยู่ลบไม่ได้
- replay รับเข้าพักสร้าง occupancy เดียว ไม่เปลี่ยนเลขเริ่มต้นย้อนหลัง
- เปลี่ยนค่าเช่าในทะเบียนห้องไม่เปลี่ยนค่าเช่าตามสัญญาเดิม
- เปลี่ยนเบอร์ชนคำขออื่นไม่เปลี่ยนชื่อ/LINE/session บางส่วน
- เปลี่ยนเบอร์สำเร็จยกเลิก session และ LINE ทั้ง active/pending; เบอร์เก่าเข้าไม่ได้
- มิเตอร์คู่ผิดไม่บันทึกครึ่งเดียว และไม่เปิดให้ออกบิลจากข้อมูลไม่ครบ
- เปลี่ยนอัตราค่าน้ำหลัง preview ทำให้ token ใช้ไม่ได้ ไม่มีบิล/รายการบิลหลุดออกมา
- เปลี่ยนชื่อห้อง/ผู้พักไม่เปลี่ยน snapshot และยอดของบิลที่ออกแล้ว
- ย้ายออกขณะมีบิลค้างไม่เปลี่ยน occupancy, สถานะห้อง หรือ session
- ยกเลิกจองปล่อยห้อง/เบอร์ได้ แต่ไม่คืนชีพคำขอเก่า
- จำลองความผิดพลาดก่อน commit รับเข้าพักแล้ว rollback ทั้ง booking/resident/occupancy/notice/audit
- ปิด/ลดสิทธิ์ตัวเองหรือเจ้าของคนสุดท้ายไม่ได้; active flags ที่ขัดกันถูกปฏิเสธ
- ปิดบัญชีผู้ดูแลแล้ว session เดิมและการ login ใหม่ใช้ไม่ได้

ปรับ `resident_phone_mysql.php` ให้เริ่มทดสอบแก้ room/occupancy ใน session
จากผู้พักที่ login ถูกต้องจริงและมี ID ครบ ไม่ให้ test ผ่านเพราะ actor เดิมหาย
หลัง HTTP probe พร้อมตรวจว่าไม่มี PHP warning ในรอบทดสอบเฉพาะชุดที่แก้

## Browser integration

ใช้ Edge headless + PHP HTTP + MySQL/session จริงบน loopback
`tests/browser-operations.mjs` ทดสอบหลัง seed ด้วย `operations_mysql.php` เท่านั้น:

- จำลอง GET ผู้พักตอบ 503 และ malformed payload: ไม่มีแถวเก่าให้ทำรายการ
  การค้นหาไม่ทำให้แถวกลับมา และปุ่มลองใหม่อ่านข้อมูลจริงกลับได้
- เปลี่ยนเบอร์ชนการจองจริง: server ตอบ 409 คงร่าง เบอร์ใน DB ไม่เปลี่ยน
- รับเข้าพักจริงผ่านฟอร์มโดยหน่วง request แล้วยิง submit ซ้ำ: ส่ง POST ครั้งเดียว
  สร้างผู้พักรายเดียว และห้องเปลี่ยนเป็น occupied
- staff เข้า owner-only API ไม่ได้; ปิดบัญชีแล้ว HTTP session เดิมได้ 401
- ลูกบ้านอ่านบิลห้องอื่นได้ 404 และเข้า admin API ไม่ได้; CSRF ผิดไม่แก้ profile
- admin ทั้ง 11 หน้าโหลดต่อได้ ไม่มี JavaScript runtime error

รันทดสอบ QR/browser จากรอบก่อนซ้ำด้วย: provider ปิดยังแสดง QR,
สามห้องยอดฐานเดียวกันได้สตางค์ไม่ซ้ำ เปิดใหม่ได้ยอดเดิม,
responsive 320/390/768/1366px และคำแนะนำบิลค้าง/ปุ่มโหลดใหม่ยังทำงาน

Browser test เป็น opt-in เพราะ repo ไม่บังคับติดตั้ง Playwright:
ใช้ฐาน `appj_operations_*` หรือ `appj_line_test_operations` ที่เพิ่งรัน operations suite,
`APP_ENV=testing`, `OPERATIONS_TEST_URL=http://127.0.0.1:<port>`,
`PLAYWRIGHT_MODULE` เป็น ESM module ที่ติดตั้งไว้ (ไม่กำหนดจะใช้ `playwright`),
และ `BROWSER_CHANNEL` (ค่าเริ่มต้น `msedge`) แล้วรัน `node tests/browser-operations.mjs`.
ห้ามใช้ฐาน/เว็บ production; ตัวทดสอบสร้างผู้พักและผู้ดูแลเฉพาะ fixture และบล็อก browser
ออกนอก loopback ส่วน PHP ใช้ credentials LINE จำลองที่เตรียมใน CLI ด้วย injected transport

ข้อจำกัด: ไม่โอนเงินจริง ไม่ส่ง LINE หรือเรียก provider จริง ไม่รับประกันทุก browser/อุปกรณ์
ก่อน deploy ต้องสำรองข้อมูล ตรวจ configuration จริง และทดสอบ staging ตามรายงานก่อน
