# คำอธิบายเมื่อทำรายการไม่ได้ — PHP/MySQL

## สิ่งที่เปลี่ยน

- เพิ่ม `action-guidance.js` ใน layout ร่วมของหน้าสาธารณะ หน้าเข้าสู่ระบบ ผู้พัก และผู้ดูแล ข้อความอยู่ใกล้ช่อง/ปุ่ม ไม่ต้องลองคลิกปุ่ม disabled หรือรอ tooltip
- แต่ละข้อความระบุสาเหตุและวิธีดำเนินการ ส่วนที่แก้ได้ในระบบมีปุ่มไปหน้าที่เกี่ยวข้องผ่านตัวตรวจสิทธิ์/ร่าง/งานที่กำลังบันทึกเดิม ไม่เรียก API แก้ไขแทนผู้ใช้
- รักษา `disabled`, `aria-busy`, validation และข้อจำกัดฝั่งเซิร์ฟเวอร์ทั้งหมด มี `aria-describedby` เชื่อมคำอธิบายกับช่อง/ปุ่ม และคงคำอธิบายเดิมที่มีอยู่แล้ว
- ขณะบันทึก รวมคำเตือนรอผลไว้ในฟอร์ม ไม่สร้างคำขอซ้ำ เมื่อสถานะกลับมาพร้อม คำอธิบายปิดปุ่มจะหายเอง
- กรอกข้อมูลไม่ครบ/ผิดรูปแบบ: คง native validation และเพิ่มข้อความข้างช่อง แก้ช่องแล้วคำเตือนหาย ไม่แก้ค่าให้เอง
- ข้อผิดพลาดจาก API ส่งต่อเป็น Error ที่มีรหัส ไม่แปลงทิ้งเป็นข้อความก่อนหาแนวทางแก้ Toast ข้อผิดพลาดอยู่จนกดปิด ส่วนข้อความสำเร็จยังหายตามเวลาเดิม
- ข้อผิดพลาดที่ไม่รู้จักใช้คำแนะนำกลางอย่างระมัดระวังและรหัสสำหรับแจ้งผู้ดูแล ไม่อ้างว่าสามารถระบุสาเหตุภายในได้ทุกกรณี

## จุดที่มีแนวทางเฉพาะ

- ใบแจ้งหนี้: แยกโหลดข้อมูลไม่สำเร็จ ไม่มีผู้พัก ไม่เลือกห้อง ทุกห้องออกบิลแล้ว ยังไม่ยืนยันค่ารายเดือน รายการอื่นไม่ครบ และยังไม่ตรวจยอดล่าสุด มีคำอธิบายซ้ำใกล้ปุ่มท้ายฟอร์มเพื่อไม่ต้องเลื่อนกลับไปอ่านด้านบน
- กรณีภาพตัวอย่าง: ห้อง 8483/1241 ที่มีบิลแล้วไม่เลือกซ้ำ มีปุ่ม “ดูบิลที่ออกแล้ว” ไม่แนะนำให้เลือกห้องที่ถูกปิดอยู่ และไม่ต้องยืนยันปิดยอดซ้ำเพียงเพื่ออ่านบิลเดิม
- แก้ข้อผิดพลาด “เลือกทุกห้อง”: input event เคยคำนวณ checked จากรายห้องเก่าก่อน change event จึงย้อนค่าที่ผู้ใช้เพิ่งคลิก ตอนนี้เปลี่ยนรายห้องและเก็บร่างก่อนคำนวณสถานะปุ่มใหม่
- LINE บิล: แยกและนับบิลรอตรวจ ชำระแล้ว ยังไม่ผูก OA ไม่พร้อม อยู่ในคิว LINE รับคำขอแล้ว และต้องตรวจผลเดิมก่อนส่งซ้ำ มีรายละเอียดรายบิลแม้บิลอื่นยังเข้าคิวได้
- LINE ผูกบัญชี: ตั้งค่าบอทไม่พร้อม ถูกระงับ ผูกอยู่แล้ว ไม่มีรหัส/บัญชีให้ยกเลิก รหัสหมดอายุ บัญชีถูกใช้ และปัญหา Token/Webhook/เครือข่าย ใช้บอทเดิมของหอ ไม่แนะนำเพิ่มบอทซ้ำ
- รับเข้าพัก/จอง/ย้ายออก: ไม่มีห้องว่าง ประวัติตัวตนซ้ำ วันเข้าพักทับกัน ข้อมูลเปลี่ยน และบิลค้าง มีทางไปตรวจห้อง ผู้พัก บิล หรือการจอง
- มิเตอร์: แยกขาดเลขเริ่มต้น ออกบิลแล้ว ประวัติขาด/ถูกอ้างอิง และตัวเลขย้อน/ผิดปกติ ไม่แนะนำใช้ศูนย์แทนข้อมูลที่ไม่ทราบ
- การชำระเงิน: สลิปรอตรวจ สลิปซ้ำ รูปแบบ/ขนาดไฟล์ผิด อัปโหลดไม่ได้ QR เก่าใช้ไม่ได้ และบัญชีรับเงินเปลี่ยน ย้ำตรวจรายการเดิมและไม่โอนซ้ำ มีคำแนะนำส่งหลักฐานเข้า LINE เมื่อแนบไม่ได้
- ตั้งค่า/สิทธิ์/เข้าสู่ระบบ: ต้องบันทึกก่อนทดสอบ เฉพาะเจ้าของ บัญชีไม่พร้อม เซสชันหมดอายุ รอผล/จำกัดคำขอ และชื่อผู้ใช้ซ้ำ โหลดค่าตั้งค่าไม่สำเร็จมีปุ่มลองอ่านใหม่

## ข้อจำกัดความปลอดภัย

- ไม่มี migration ไม่มีการเปลี่ยนยอดเงิน การยืนยันชำระ การจองทศนิยม หรือกลไกป้องกันข้อความซ้ำ
- ข้อความใช้ textContent และปลายทางแบบ allowlist ไม่ใช้ HTML/URL/selector จากข้อความผิดพลาดเป็นคำสั่ง
- ไม่เปิดหน้าตั้งค่าเจ้าของให้ staff/ผู้พัก ปุ่มไปแก้ไขไม่ข้ามการยืนยันละทิ้งร่างหรือการล็อกระหว่างบันทึก
- ไม่มีการทดสอบส่ง LINE จริง เรียกผู้ตรวจสลิปจริง หรือโอนเงินจริง งานนี้ทดสอบบน loopback และฐานข้อมูลชั่วคราวเท่านั้น

## การตรวจสอบ

- PHP unit/contract: 127 ผ่าน; JavaScript: 230 ผ่าน
- เพิ่ม unit tests สำหรับทุกห้องออกบิลแล้ว สาเหตุ LINE และจำนวนบิล คำแนะนำตามสิทธิ์ ข้อความที่ไม่เชื่อถือ และ error toast ที่ต้องกดปิด
- MySQL 18 ชุด: 253 กลุ่มผ่าน ครอบคลุม QR, การรับเข้าพัก, LINE, การออกบิล, มิเตอร์, ผู้พัก, สลิป, ยอดโอน, health และ lifecycle
- Browser operations + action guidance: การทำงานจริงตามสิทธิ์ อ่านข้อมูลล้มเหลว ร่างไม่หาย ทุก 11 หน้าผู้ดูแล และกรณีบิลจำลองที่กั้นการเขียน API ไว้ ทดสอบ 320/390/1280 px
- Browser transfer: QR ที่ไม่ได้เปิดตรวจสลิป ยอด 3 ห้องไม่ซ้ำและไม่เปลี่ยนเมื่อโหลดใหม่ การป้องกันย้ายออก และ 320/390/768/1366 px
- การทดสอบ scroll รอปลายทางปรากฏจริง เนื่องจากหน้าใช้ smooth scrolling ไม่ตัดสินจาก animation frame แรก

รันชุด JavaScript ด้วย `node --test tests/*.test.js` และ PHP ด้วย `php tests/run.php` ส่วน `tests/browser-operations.mjs` ต้องใช้ fixtures ของ `operations_mysql.php` ในฐานข้อมูลทดสอบแยกเท่านั้น ไม่ใช้กับ production
