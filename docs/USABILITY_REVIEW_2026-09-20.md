# ใช้งานง่ายและป้องกันข้อผิดพลาด — 20 กันยายน 2026

## ขั้นตอนใช้งานที่ลดลง

**LINE:** ตั้งค่า LINE Bot → กรอก Token และ Secret → ตรวจชื่อบัญชีที่ระบบดึงให้ → คัดลอก Webhook URL ไป Verify ที่ LINE Developers ไม่ต้องกรอกชื่อ รหัสภายใน Basic ID Channel ID หรือ URL เอง การผูกผู้พัก/ผู้รับแจ้งเตือนเลือกบอทหลักให้โดยอัตโนมัติ

**ออกบิล:** บันทึกอัตราและระยะชำระครั้งเดียวในตั้งค่า → จดมิเตอร์ → เลือกรอบเดือน → ตรวจห้องที่ระบบเลือกให้ (เฉพาะห้องมีผู้พักและยังไม่ออกบิล) → ตรวจยอด → ยืนยัน ไม่ต้องกรอกค่าเช่า มิเตอร์เดิม อัตราหรือกำหนดชำระซ้ำ ค่าใช้จ่ายพิเศษยังระบุได้เมื่อจำเป็นและจะแสดงชัดว่าเป็นยอดต่อห้อง

**การเชื่อมต่อ:** ค่าเทคนิคการส่งซ้ำ ขนาดคิว ขนาดสลิปและช่วงเผื่อเวลาเป็นข้อมูลอ่านอย่างเดียวและคงค่าที่บันทึกไว้เดิม ไม่ส่งค่าว่างหรือ null ไปทับเมื่อบันทึกฟอร์มธุรกิจ

ข้อมูลที่ต้องรู้จากผู้ดูแลจริงยังต้องระบุ เช่น ราคา ค่าเช่า เลขมิเตอร์จริง บัญชีรับเงินและคีย์ผู้ให้บริการ ระบบไม่เดาข้อมูลการเงินหรือคีย์ที่ไม่สามารถดึงได้

## สิ่งที่ป้องกันเพิ่ม

- ผลโหลดห้องหรือบิลเก่าไม่ทับข้อมูลล่าสุด และผลผิดพลาดเก่าไม่ซ่อนผลใหม่ที่สำเร็จ
- ระหว่างเปลี่ยนรอบบิลหรือโหลดไม่สำเร็จ ปุ่มตรวจยอด ออกบิลและส่ง LINE ถูกปิด รวมถึงตรวจซ้ำใน event handler
- ค่าบิลที่ไม่ส่งมาจากฟอร์มคำนวณบนเซิร์ฟเวอร์ ไม่ใช้ hidden input กำหนดอัตราหรือวันครบกำหนด ค่าอัตราถูกล็อกขณะออกบิล และ preview token ป้องกันการเปลี่ยนอัตรา/กำหนดชำระหลังตรวจยอด
- เลือกห้องให้อัตโนมัติไม่ได้แปลว่าออกบิลอัตโนมัติ ยังบังคับ preview และยืนยัน โดยเดือนปัจจุบันต้องยืนยันปิดยอดต่างหาก
- ฟอร์มจองล็อกระหว่างส่งและกัน submit ซ้ำ ข้อมูลที่ส่งแล้วไม่เปลี่ยนระหว่างรอผล
- LINE รับเฉพาะคีย์และสถานะจากฟอร์ม ปฏิเสธการกรอก metadata เอง ตรวจ provider identity เดิมก่อนหมุน Token และไม่ยืนยัน webhook จากการทดสอบ Token อย่างเดียว
- คีย์ว่างเก็บของเดิม การล้างต้องยืนยันและปิดบอทพร้อมกัน การหยุด/เปิดไม่คืนบัญชีที่ถูกยกเลิก และ action ของ dialog ไม่ทำงานข้ามชนิดหน้าต่าง
- แก้การอ้างชื่อปุ่มกับ HTML และเพิ่มการทดสอบจาก template จริง ไม่พึ่ง DOM จำลองอย่างเดียว

## ผลตรวจในเครื่องก่อนส่งขึ้น main

PHP syntax **78 ไฟล์ผ่าน**, JavaScript syntax 2 ไฟล์ผ่าน, shell syntax ผ่าน; PHP unit/contract: **110 ผ่าน**; JavaScript interaction/HTML contract: **94 ผ่าน**, ไม่มี failed/cancelled/skipped

MySQL **11 ชุดผ่าน** บน Oracle MySQL 8.4.10 โดยสร้างฐานและ data directory ใหม่เฉพาะการตรวจ ผูก `127.0.0.1:33337` และใช้บัญชี runtime SELECT/INSERT/UPDATE แยกจาก schema owner: migration 015, pending opening readings, LINE binding, LINE bot, room binding, single-bot OA, LINE platform, billing delivery, automatic billing defaults, healthz และ lifecycle รวม schema audit ผ่าน

ชุด automatic billing defaults ตรวจอัตรา/ยอด/วันครบกำหนดที่ดึงเอง การไม่ข้ามการยืนยันตั้งค่า null ที่ไม่ถูกต้อง การเปลี่ยนค่าหลัง preview การล็อกค่ากับ connection อื่น และการออกบิลซ้ำ

CI แยกฐานทดสอบ billing delivery ออกจาก LINE platform และเพิ่ม billing defaults เพื่อไม่ให้ใช้ registry ที่มีตัวตนจากชุดก่อนค้างอยู่ รันทดสอบ PHP/JavaScript ซ้ำใน Windows ได้ด้วย `scripts\test-local.cmd`

## ขอบเขตและการอัปเกรด

ไม่แก้ `.env`, APP_KEY, รหัสผ่านจริง หรือข้อมูลผู้พัก/บิลจริง ไม่รัน worker ส่งข้อความจริง และไม่ใช้คีย์ provider จริง ผลทดสอบ LINE/การตรวจสลิปใช้ transport หรือหลักฐานจำลอง ไม่ใช่การรับรองธุรกรรมธนาคารหรือมือถือ LINE จริง การทดสอบ JavaScript เป็น interaction harness และตรวจ HTML ไม่ใช่ visual acceptance บนเบราว์เซอร์ทุกชนิด

งานนี้รวมการเปลี่ยนแบบบอทเดียวที่มีอยู่ใน working tree ก่อนเริ่มตรวจ ไม่แก้ schema เพื่อย้ายผู้รับไปบอทอื่น หากฐานที่ใช้งานจริงเคยมี OA ID มากกว่า 0 ต้องสำรองและตรวจบัญชี การผูก และคิวเก่าก่อน deploy การย้าย Token ข้ามบอทหรือเดาการจับคู่ผู้รับไม่ได้รับอนุญาตโดยอัตโนมัติ

เก็บสำเนา source ก่อนแก้และ log รายชุดไว้ใน `storage/logs/usability-main-20260920/` ซึ่งถูก git ignore ไฟล์ตั้งค่าทดสอบและฐานจำลองไม่อยู่ใน commit ควรทดสอบ LINE webhook/แชตและการรับชำระกับบัญชีจริงบน staging ก่อนเปิดรับผู้พักจริง

ค่า `.env` ของเครื่องนี้เป็นชุด production ที่มีการอ้างตัวแปรแพลตฟอร์ม ไม่ใช้เป็นฐานสำหรับเปิดเว็บ local การทดสอบใช้ environment และ php.ini แยก ไม่เปลี่ยน PHP configuration ส่วนกลาง
