## กรณีที่ตรวจ

- คืนพักใช้ช่วงเข้าแบบรวมวันเข้า และออกแบบไม่รวมวันออก ห้องเดียวกันรับคนละช่วงได้ แต่ช่วงซ้อนหรือสองคำขอพร้อมกันมีผู้ชนะหนึ่งรายการ
- quote ผูกวันที่ จำนวนคน ราคา และรุ่นข้อมูลห้อง; เปลี่ยนข้อมูลหรือ quote หมดอายุไม่สร้างการจองด้วยราคาเก่า
- ส่งคำขอเดิมซ้ำคืนรายการเดิม พร้อม token เดิม; เปลี่ยนข้อมูลแล้วใช้ key เดิมถูกปฏิเสธ
- token อ่านได้เฉพาะการจองของตน ไม่เปิดประวัติด้วยชื่อ/เบอร์หรือเลขอ้างอิงอย่างเดียว
- รับเงินเต็มยอดก่อนเข้าพัก; ตรวจสลิปมี lease และ retry quota 20 ครั้ง/24 ชั่วโมง ซึ่งกู้คืนได้หลัง cooldown
- สลิปรอตรวจ/พักตรวจและ bank reference ที่ยืนยันเงินแล้วใช้ซ้ำข้ามรายวัน/รายเดือนไม่ได้; สลิปที่ถูกปฏิเสธสามารถตรวจใหม่กับรายการที่ถูกต้องโดยตรวจธนาคารครบ และคงประวัติการปฏิเสธเดิม
- ผลตรวจเงินที่จบหลังยกเลิก/หมดอายุไม่คืนชีวิตสิทธิ์ห้อง แต่คงใบรับเงินและงานคืนเงิน
- เงินคืนพร้อมกันสอง process ไม่คืนเกินยอด แม้ bypass service precheck ด้วย INSERT โดยตรงในฐานทดสอบ
- เงินประกันคืน/หักครบก่อนออก; cash receipt และ refund reference ซ้ำตอบ conflict พร้อม rollback counter
- ยอด QR อยู่ใน pool เฉพาะที่ active/พักยอด; พ้น 7 วันจึงใช้ซ้ำได้ ไม่มีการจับคู่เงินอัตโนมัติจากยอด และ QR/ใบรับเงินเก่าไม่ถูกแก้ไข
- สลิปรอตรวจไม่ปล่อยช่องยอด; legacy receipt ที่ปล่อยช่องแล้วคง verified, bank reference และยอดเดิม
- action key เดิมหลังมีงานใหม่คืนสถานะล่าสุด ไม่แสดงว่าห้องพร้อมเมื่อมีการเช็กเอาต์ใหม่
- เช็กเอาต์ก่อนกำหนดยังคงคืนที่จองไว้ และห้ามเปลี่ยนเป็นรายเดือน/ลบห้องเพื่อหลบสิทธิ์นั้น
- daily booking ไม่สร้าง monthly occupancy/bill/meter; ประวัติรายเดือนเดิมยังอยู่
- source ต้องผ่าน migration markers และ schema comparison ที่รักษาวงเล็บ/literal; ระบบไม่เปิดรับงานจาก schema ที่ถูกทำให้ guard อ่อนลง

## ข้อผิดพลาดที่แก้ในรอบตรวจซ้ำ

| พฤติกรรมเดิม | ผลหลังแก้ |
|---|---|
| คำตอบส่งสลิปหาย แต่ผลสลิปเก่าที่ถูกปฏิเสธอาจเปิดปุ่มโอนใหม่ | เก็บคำขอที่ไม่ทราบผลข้ามรีโหลด ตรวจ/ส่งไฟล์เดิมด้วย SHA-256 และไม่ถือผลเก่าเป็นผลใหม่ |
| การจองหมดเวลาแล้วส่งหลักฐานเงินที่โอนไปไม่ได้จากหน้าจอ | ส่งหลักฐานหลังหมดเวลา/ยกเลิกได้; เจ้าของส่งแทนเมื่อแท็บผู้จองหาย โดยไม่คืนสิทธิ์ห้องที่หมดไป |
| ไฟล์ pending หายหรือเสียหาย ค้างตรวจไม่มีทางกู้ | พักตรวจโดยยังถือว่าเงินไม่แน่นอน กู้เฉพาะ HMAC/MIME เดิมและตรวจต่อได้ เก็บ action history |
| หลักฐานส่งผิดรายการและถูกปฏิเสธล็อกไฟล์/เลขธนาคารไว้ถาวร | ปล่อยเฉพาะ projection ของ rejected; หลักฐาน pending/closed/verified ยังป้องกันใช้ซ้ำและเก็บ raw history |
| quote/hold อาจเลยวันออกจนยืนยันช่วงที่เข้าพักไม่ได้ | หมดอายุไม่เกินเที่ยงคืนวันออกตามเวลาไทย รวม legacy hold และผลการเงิน |
| expiry ที่เกิดใน route มี transaction ชั้นนอกถูก rollback พร้อม 409 | commit สถานะหมดอายุ audit และคืนกันห้องก่อนตอบ 409 |
| ห้องที่เช็กเอาต์ก่อนกำหนดอาจแสดงว่าง; ลดความจุต่ำกว่าการจองเดิมได้ | คงคืนที่ชำระแล้ว แสดง reserved และกันลดความจุทั้ง API/SQL |
| เจ้าของสองคนใช้หน้าห้องเก่าทับข้อมูลกัน | PUT ต้องส่ง catalogue HMAC รุ่นปัจจุบัน; 409 เก็บร่างและไม่เปลี่ยนข้อมูลรุ่นใหม่ |
| ประวัติมิเตอร์ของห้องที่เปลี่ยนเป็นรายวันยังแสดงช่องให้บันทึก | อ่านอย่างเดียวพร้อมเหตุผล; รายวันไม่ถูกนับเป็นงานมิเตอร์/ออกบิลรายเดือน |
| เจ้าของถูกเพิกถอนสิทธิ์ระหว่างรอผล provider แต่ใช้ actor เก่าตอน commit | ตรวจสิทธิ์และ auth_version ด้วย FOR SHARE ก่อน commit; คงหลักฐาน pending ให้เจ้าของที่มีสิทธิ์ตรวจต่อ |
| bootstrap ตรวจ generated definitions รายวันไม่ครบ; คู่มือยังบอกโครงสร้างรุ่นเก่า | สร้าง predicate/metadata จาก canonical source ตรวจ bootstrap จริง และอัปเดตคู่มือถึง migration 020 |

Migration fixture จำลอง schema 019 ที่ใช้ unique บน raw HMAC/transaction_ref และไม่มี closed/actions โดยคง guards 019 ที่ไม่ได้เปลี่ยนไว้ ทดสอบ 020 แล้วเทียบ trigger bodies ทั้งการเงินและห้องกับ canonical ไม่อ้างว่าการลบ guards ที่ไม่เกี่ยวข้องเป็นการอัปเกรดรุ่นเก่า

กรณี generated CASE ที่เป็นการจัดกลุ่มกำกวม MySQL อาจปฏิเสธ DDL ด้วย error 1292 ก่อนติดตั้ง ชุดตรวจรับการปฏิเสธนี้เฉพาะกรณีที่กำหนดและตรวจว่านิยาม canonical ยังครบ; ไม่อ้างว่าติดตั้งนิยามที่ MySQL ปฏิเสธได้สำเร็จ
