# แก้ค้างหลังบันทึก LINE และตรวจสถานะจริง — 20 กันยายน 2026

## สาเหตุที่ทำซ้ำได้ในเบราว์เซอร์

หลังบันทึก OA เดิมเรียก `closeDialog(dialog)` แล้ว `openWebhook(0)` ทันทีบน dialog เดียวกัน เหตุการณ์ `close` ของ HTML dialog ถูกส่งภายหลังและไปเรียก `resetDialog()` ของหน้าสถานะที่เปิดใหม่ ทำให้ล้างรายละเอียด เปลี่ยน epoch/mode และไม่รับผลอ่านสถานะที่กำลังตามมา เหลือข้อความกำลังโหลดหรือหน้าต่างว่าง ชุด DOM จำลองเดิมส่ง close แบบทันทีจึงไม่เจอปัญหานี้

แก้ให้เปลี่ยนจากฟอร์มไปหน้าสถานะใน dialog เดิมโดยไม่ปิดแล้วเปิดใหม่ และไม่ให้ close event เก่าล้าง dialog ที่เปิดใหม่แล้ว ทดสอบซ้ำกับ Microsoft Edge และเพิ่ม regression ทั้งการจำลอง close ที่มาช้าและการห้ามปิด/เปิดซ้ำหลังบันทึก

อีกจุดคือ catch ของการอ่านข้อมูลเดิมแจ้ง error แต่ไม่ยกเลิกข้อความกำลังโหลด และ Promise.all ของรายชื่อ OA/ผู้รับทำให้ข้อมูลบอทไม่แสดงเมื่อโหลดผู้รับล้มเหลว ปรับเป็นสถานะ loading/error/ready ชัดเจน มีปุ่มลองใหม่ และแสดงผลแต่ละส่วนแยกกัน

## วิธีใช้

เปิด **บัญชี LINE OA** แล้ว **ตั้งค่า LINE Bot** กรอก Token และ Channel secret จาก Messaging API บัญชีเดียวกัน บันทึกแล้วเห็นชื่อบัญชีและ Webhook URL ทันทีจากผลตอบกลับ ไม่รอการโหลดรอบใหม่จึงค่อยแสดง

กด **ตรวจการเชื่อมต่อจริง** ระบบอ่านตัวตนบอทและการตั้งค่า Webhook จาก LINE แยกผลว่า URL ตรงหรือไม่ เปิด Use webhook หรือไม่ และระบบเคยได้รับ callback ที่ตรวจลายเซ็นผ่านหรือยัง เมื่อ URL ไม่ตรงให้คัดลอก URL ที่ระบบสร้างไปวางใน LINE Developers เปิด Use webhook/Webhook redelivery แล้วกด Verify ไม่ต้องกรอกชื่อหรือ Basic ID เอง

สถานะรับ Webhook เป็นหลักฐานในอดีต ไม่แทนการทดสอบข้อความใหม่หรือยืนยันว่า worker ส่งบิลกำลังทำงาน หากหน้าตรวจผ่าน ให้เพิ่มเพื่อนและพิมพ์ **เมนู** หรือ **สถานะ** ในแชต ข้อความทั่วไปไม่ได้เรียกให้บอทตอบ การส่งบิลแบบคิวต้องตรวจ worker ที่หน้า **ภาพรวม** แยกต่างหาก

## การป้องกันและขอบเขตเวลา

คำขออ่านของหน้า LINE มี hard deadline 12 วินาที คำขอบันทึก/ตรวจ 30 วินาที และยกเลิก transport เมื่อหมดเวลา แม้ transport ไม่คืนผลหลัง abort ตัวหน้าต่างยังคืนการควบคุมได้ หลังบันทึกที่ไม่ทราบผลจะแจ้งให้ **ตรวจค่าที่บันทึก** ก่อนส่งซ้ำ ไม่ส่งคำขอซ้ำเอง และไม่ล้างคีย์ที่กรอกเมื่อคำขอล้มเหลว

ฝั่งเซิร์ฟเวอร์คงการตรวจ TLS เต็มรูปแบบ ติดต่อ LINE ไม่เกิน 8 วินาทีต่อคำขอและรอเชื่อมต่อไม่เกิน 3 วินาที การรอ registry lock สำหรับ setup ไม่เกิน 2 วินาทีและ row lock ไม่เกิน 3 วินาที ไม่ให้ generic retry ทำให้การตรวจคีย์ช้าซ้ำหลายรอบ ค่าการรอของ connection ถูกคืนเมื่อจบงาน

การอ่านการตั้งค่า Webhook จาก LINE ทำหลังปล่อย transaction/registry lock ของการตรวจตัวตนแล้ว ตรวจ fingerprint ของการตั้งค่าก่อน/หลังเพื่อปฏิเสธผลที่ถูกค่าชุดใหม่แทรกระหว่างตรวจ ไม่มีการเปลี่ยน Webhook URL บนบัญชี LINE ให้อัตโนมัติหรือย้าย Token ข้ามบอท

แยกข้อความ Token ถูกปฏิเสธ, DNS ผิดพลาด, SSL/CA ไม่ผ่าน, timeout, จำกัดการเรียก API, ยังไม่ตั้ง URL, URL ไม่ตรง, Use webhook ปิด และรอ callback ไม่ส่ง curl_error, provider body, header หรือคีย์จริงกลับไปบนหน้าเว็บ ผลตรวจล่าสุดที่ไม่ผ่านไม่ถูก polling อ่านฐานสำเร็จลบทิ้งโดยเข้าใจผิดว่าตรวจ LINE ผ่าน

## ตรวจเพิ่มเติมก่อนส่ง main

แยกคำว่า Token ที่ **เคยตรวจผ่าน** ออกจาก Token ที่ **ถูก LINE ปฏิเสธในการตรวจล่าสุด** ผลอ่านฐานสำเร็จไม่กลบผลตรวจ LINE ที่ล้มเหลว และหากได้รับข้อผิดพลาด Webhook ใหม่หลังตรวจผ่าน จะไม่คงแถบสถานะผ่านไว้ ผลตรวจที่เกิน 60 วินาทีจะเตือนให้ตรวจ LINE ใหม่ ไม่ยืดอายุจากการ polling ฐานข้อมูล

หน้ารายชื่อการผูก LINE ล้างข้อมูลเก่าขณะเริ่มโหลดและเมื่อโหลดล้มเหลว การเปลี่ยนตัวกรองไม่ทำให้ข้อมูลเดิมกลับมา คำตอบผิดรูปแบบไม่ถูกนับเป็นรายการว่างที่โหลดสำเร็จ และผลจากคำขอเก่าไม่เขียนทับผลใหม่ มี regression เพิ่มอีก 6 ข้อครอบคลุมกรณีเหล่านี้

ผลตรวจรอบสุดท้ายแยกไว้ใน `storage/logs/line-connection-20260920/verification/` และ `verification-mysql/` โดยใช้ข้อมูลจำลองและสำเนา source ที่ไม่รวม `.env` เซิร์ฟเวอร์ทดสอบที่สร้างในรอบนี้จะถูกหยุดหลังรันทดสอบ ไม่เปลี่ยนหรือหยุด process อื่นที่ใช้งานอยู่
